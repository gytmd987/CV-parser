# 대시보드 — 구현 계획

> 코드는 아직 없습니다. **어떻게 만들지 정하는 문서**입니다.
> 검토하고 "이렇게 가자" 를 정해 주시면 그때 만듭니다.

## 무엇을 원하시는지 (제가 이해한 것)

1. 메일처럼 **여러 대시보드를 템플릿으로** 만들고 목록에서 고른다.
2. 구성은 **사람이 직접** 한다. 어렵지 않아야 한다.
3. 기본 단위는 **표**다.
4. 행·열 이름을 사람이 정하고, **엑셀 수식처럼 칸마다** 무엇이 어떤 형식으로
   들어갈지 지정한다.
5. SQL 을 쓸 줄 아는 사람이 없으니, **예시를 주면 LLM 이 알아서 구성**해 준다.

아래는 이 다섯 가지를 그대로 만드는 계획입니다.

---

## 1. 핵심 결정 — SQL 을 쓰지 않습니다

가장 중요한 갈림길입니다. "칸마다 내용을 지정한다" 를 SQL 로 풀면 안 됩니다.

- **위험합니다.** 지원자 DB 에는 이름·연락처·생년월일이 있습니다. 임의 SQL 을
  칸에 적을 수 있으면, 대시보드 하나로 개인정보 전체를 뽑아낼 수 있습니다.
  현업이 자기 과제만 봐야 한다는 규칙도 SQL 앞에서는 무력합니다.
- **어차피 못 씁니다.** 말씀하신 대로 쓸 사람이 없습니다.
- **LLM 이 만든 SQL 을 그대로 돌리는 건 더 나쁩니다.** 틀려도 조용히 그럴듯한
  숫자가 나옵니다. 대시보드에서 조용히 틀린 숫자는 최악입니다.

그래서 **이 데이터 전용의 작은 수식 언어**를 만듭니다. 엑셀 수식과 같은 감각이고,
할 수 있는 일이 정해져 있어 안전하며, 사람이 읽고 고칠 수 있습니다.

```
=COUNT(지원자)                              지원자 몇 명
=COUNT(지원자, 박사_학교="한국대학교")          그중 조건에 맞는 사람
=COUNT(채용, 최종상태~"*합격")                 채용 중인 사람 중 최종상태가 합격으로 끝나는 사람
=COUNT(채용, 부서="차세대공정", 서류검토="합격")   조건 여러 개는 AND
=PCT(채용, 서류검토="합격")                    같은 모집단 대비 비율 (%)
=AVG(지원자, 해외논문수)                       평균
=MAX(채용, 매칭점수)                          최고값
=LIST(채용, 부서="차세대공정", 열=한글_이름)      이름 나열 (권한 있는 사람만)
```

| 부분 | 무엇 |
|---|---|
| **함수** | `COUNT` `PCT` `AVG` `SUM` `MIN` `MAX` `LIST` — 이게 전부입니다 |
| **대상** | `지원자` (인재 Pool 전체) / `채용` (채용 시작한 사람) / `논문` / `경력` / `매칭` |
| **조건** | `열="값"` `열~"패턴*"` `열>숫자` `열≠"값"` — AND 로만 이어집니다 |
| **열 이름** | **표 항목 탭에 있는 그 이름 그대로**입니다. 새로 외울 게 없습니다 |

> 왜 이 정도로 충분한가 — 지금 화면에 있는 숫자들(`인재 Pool 12명 · 채용 중 3명`,
> 최종상태별 인원, 부서별 인원)이 전부 이 다섯 함수로 나옵니다.
> 모자라면 함수를 하나씩 늘리면 됩니다. 늘릴 때마다 안전한지 볼 수 있습니다.

### 계산은 지금 쓰는 데이터를 그대로 씁니다

새 질의 계층을 만들지 않습니다. 표 화면들이 이미 쓰는 것과 **같은 것**을 씁니다.

```
store.list_all()      지원자 레코드
recruit.all()         채용 진행 (부서·과제·단계·최종상태)
recruit.started()     채용 시작한 사람
store.custom_map()    추가한 열 값
store.matches(cid)    과제 매칭 점수
```

덕분에 **화면에 보이는 숫자와 대시보드 숫자가 어긋날 수 없고**, 현업의
과제 범위 제한이 공짜로 따라옵니다 (같은 `visible_project_ids` 를 지나갑니다).

## 2. 표를 만드는 두 가지 방법

### (가) 축이 있는 표 — 칸을 일일이 안 적습니다

실제로 필요한 표는 대개 이 모양입니다.

```
행 축: 부서 (자동 — 부서·과제 화면에 등록된 것)
열 축: 단계 (자동 — 표 항목의 단계 상태 목록)
칸  : =COUNT(채용, 부서={행}, 최종상태~"{열}*")
```

| | 서류 검토 | 전화 면접 | 기술 면접 | HR 면접 |
|---|---|---|---|---|
| 차세대공정 | 12 | 7 | 3 | 1 |
| 소재분석 | 8 | 5 | 2 | 2 |

- 부서가 하나 늘면 **표가 알아서 한 줄 늘어납니다.** 손댈 게 없습니다.
- 축으로 쓸 수 있는 것: 부서 / 과제 / 단계 / 최종상태 / 등록년도 / 선택형 열
  (`현재_신분` 처럼 값이 정해진 열) / 직접 적은 목록.
- 칸 수식은 **하나**입니다. `{행}` `{열}` 이 자동으로 치환됩니다.

### (나) 자유 표 — 칸마다 따로

"이 표는 그냥 이렇게 생겼으면 좋겠다" 는 경우입니다. 행·열 이름을 직접 적고,
칸마다 수식을 따로 넣습니다. 수식 대신 **그냥 글자**를 넣어도 됩니다.

```
        │ 이번 분기        │ 작년 같은 기간
────────┼─────────────────┼────────────────
접수     │ =COUNT(지원자, 등록년도="2026") │ =COUNT(지원자, 등록년도="2025")
채용 시작 │ =COUNT(채용, 등록년도="2026")   │ =COUNT(채용, 등록년도="2025")
최종 합격 │ =COUNT(채용, 최종상태="최종 합격") │ …
```

## 3. 칸의 "형식"

수식과 별개로 **어떻게 보일지**를 칸(또는 열/표 전체)에 겁니다.

| 형식 | 보기 |
|---|---|
| 정수 | `12` |
| 소수 1자리 | `3.4` |
| 퍼센트 | `58.3%` |
| 쉼표 | `1,204` |
| 사람 수 | `12명` |
| 글자 | 그대로 |

거기에 **조건부 색**을 겁니다 — `0 이면 회색`, `>= 10 이면 파랑`, `불합격이면 빨강`.
지금 표에서 쓰는 배지(`pill`) 색을 그대로 씁니다.

## 4. LLM 이 만들어 주는 부분

핵심 원칙 하나: **LLM 은 정의만 씁니다. 계산은 절대 안 합니다.**

```
사람: "부서별로 단계별 인원 보여주는 표"
  또는 붙여넣은 엑셀 예시 표
        ↓
LLM (guided_json 으로 정해진 모양의 JSON 만 나오게)
        ↓
표 정의 = {행축, 열축, 칸 수식, 형식}
        ↓
검사 — 함수가 목록에 있나 / 열 이름이 진짜 있나 / 대상이 맞나
        ↓
사람이 화면에서 수식을 눈으로 보고 고칩니다  ← 여기가 중요
        ↓
저장 → 계산은 우리 코드가 합니다
```

- 만들어진 수식은 **감춰지지 않습니다.** 각 칸에 `=COUNT(채용, 부서={행})` 이
  그대로 보이고 고칠 수 있습니다. "LLM 이 알아서 했는데 왜 이 숫자가 나오는지
  모르겠다" 가 되면 안 됩니다.
- 검사에서 **모르는 열 이름이나 없는 함수가 나오면 저장을 막고**, 무엇이
  틀렸는지 알려줍니다. 없는 열을 지어내는 건 LLM 이 가장 자주 하는 실수입니다.
- **LLM 이 없어도 전부 손으로 됩니다.** LLM 은 첫 초안을 빨리 만드는 도구일 뿐,
  기능이 거기 매달리지 않습니다. (vLLM 이 내려가 있어도 대시보드는 돌아갑니다.)

### 붙여넣기로 만들기

말씀하신 "예시 형식을 넣으면" 이 부분입니다. 엑셀에서 만들어 둔 빈 표를
그대로 붙여넣으면(TSV), 행·열 이름을 읽고 각 칸에 뭘 넣을지 LLM 이 제안합니다.
이미 `표에서 범위 복사`(TSV) 기능이 있어서 왕복이 자연스럽습니다.

## 5. 화면

```
대시보드 (탭)
├── 목록                     메일 템플릿 목록과 같은 모양
│    └── [보기] [편집] [복제] [삭제]
├── 보기       계산된 표들. 엑셀 내려받기 · 정렬 · 찾기가 이미 되는 표를 그대로 씀
└── 편집
     ├── 블록 추가:  [표] [숫자 한 개] [글]
     ├── 표 설정:    이름 / 축이 있는 표 ↔ 자유 표 / 행축 / 열축 / 형식
     ├── 칸 수식:    표 모양 그대로 놓고 칸을 눌러 고침
     ├── [LLM 으로 만들기]  말이나 붙여넣은 표로 초안 만들기
     └── [미리보기]  저장 전에 실제 숫자로 확인
```

- **블록** 을 여러 개 쌓습니다. 표 하나짜리 대시보드도 되고, 큰 숫자 몇 개 +
  표 두 개도 됩니다.
- 표는 지금 쓰는 `.scroll table` 그대로라 **정렬·찾기·엑셀 내려받기·범위 복사가
  공짜로** 따라옵니다.
- 1단계에서는 **그래프를 넣지 않습니다.** 폐쇄망이라 차트 라이브러리를 못 받고,
  직접 그리려면 인라인 SVG 를 써야 합니다. 표가 먼저 쓸모 있고, 그래프는
  나중에 막대 그래프 정도로 붙일 수 있습니다.

## 6. 저장 구조

기존 DB 는 건드리지 않고 `dashboard.db` 를 새로 만듭니다.

```
dashboards   id · 이름 · 설명 · 만든이 · 만든일시 · 수정일시 · 공개범위
blocks       id · dashboard_id · 순서 · 종류(표/숫자/글) · 제목 · 설정_json
cells        id · block_id · 행 · 열 · 수식 · 형식 · 색규칙
```

- 축이 있는 표는 `cells` 가 한 줄(대표 수식)이고, 자유 표는 칸마다 한 줄입니다.
- `설정_json` 에 행축·열축 정의가 들어갑니다.

## 7. 권한

| 역할 | 볼 수 있는 것 |
|---|---|
| 관리자 | 전부 + 편집 |
| 채용담당자 | 전부 + 편집 |
| 현업 | **공개된 대시보드만, 자기 과제 범위 숫자로** |

- 새 권한 `대시보드_조회` / `대시보드_편집` 을 만들고, 새 주소는
  `tests/test_route_permissions.py` 정책 표에 등록합니다 (거기 안 적으면
  테스트가 깨지므로 빠뜨릴 수 없습니다).
- 현업이 보는 숫자는 **자기 과제로 걸러진 뒤** 계산됩니다. 같은 대시보드라도
  사람에 따라 숫자가 다릅니다. 화면에 그렇게 적어 둡니다.
- `LIST` 처럼 **사람을 나열하는 함수**는 `지원자_목록` 권한이 있어야 값이
  나옵니다. 없으면 칸에 `(권한 없음)` 이라고 표시합니다. 대시보드가
  개인정보 우회로가 되면 안 됩니다.

## 8. 만드는 순서

| 단계 | 내용 | 크기 |
|---|---|---|
| **1** | 수식 언어(파서 + 계산기) + 단위 테스트. 화면 없음 | 중 |
| **2** | `dashboard.db` + 대시보드 목록/보기 화면, 자유 표만 | 중 |
| **3** | 축이 있는 표 (`{행}` `{열}` 치환, 자동 축) | 중 |
| **4** | 형식·조건부 색, 숫자 블록, 글 블록 | 소 |
| **5** | LLM 초안 만들기 (말 → 정의, 붙여넣은 표 → 정의) + 검사 | 중 |
| **6** | 권한·현업 범위 제한, 라우트 정책 표 등록, 엑셀 내려받기 | 소 |

1~2 단계만 있어도 쓸 수 있습니다. 3 단계부터 실제로 편해집니다.
5 단계(LLM)는 **마지막**입니다 — 손으로 되는 게 먼저 있어야 LLM 이 만든 것이
맞는지 사람이 확인할 수 있습니다.

## 9. 결정해 주셔야 하는 것

1. **실제로 쓰실 표 2~3개를 알려주세요.** (엑셀로 그려서 붙여넣어 주셔도 됩니다.)
   수식 언어에 어떤 함수가 필요한지가 여기서 정해집니다. 지금 다섯 함수는
   제 추측입니다.
2. **현업에게 대시보드를 보여줄지.** 안 보여주면 권한 부분이 많이 단순해집니다.
3. **기간 개념이 필요한지** — "이번 달", "최근 3개월" 같은 것. 지금 날짜 정보는
   `등록년도`(연 단위)뿐입니다. 월 단위가 필요하면 `등록일시` 를 쓰는
   `기간=` 조건을 넣어야 합니다.
4. **그래프가 1단계에 꼭 필요한지.** 표로 먼저 가는 걸 권합니다.

## 10. 안 하는 것

- **임의 SQL 입력칸** — 개인정보 노출 통로입니다. 어떤 형태로도 넣지 않습니다.
- **LLM 이 계산까지** — 숫자는 우리 코드가 냅니다. LLM 은 정의만 씁니다.
- **외부 차트 라이브러리** — 폐쇄망에서 못 받습니다.
- **실시간 갱신** — 화면을 열 때 계산합니다. 느려지면 그때 캐시를 답니다
  (몇백 명 규모에서는 필요 없을 겁니다).
