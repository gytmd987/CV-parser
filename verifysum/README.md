# 검증 자료 정리 (verifysum)

후보자별 검증 의견(2장짜리 워드) 30~40개를 받아 두 파일을 만든다.

1. **1장 통합본** — 사람마다 1장으로 줄이고 문체를 통일해 한 파일로 (사람마다 새 쪽)
2. **개인별 검증결과 요약** — 후보자 · 전문성/성과 · 연구전문가 역량 · 결과(추천) 표

지원자 관리(cvtool)와는 따로 도는 앱이다. LLM 서버 설정만 같은 `.env`(`CVTOOL_LLM_*`)를 쓴다.

## 켜기

```bash
python3 /경로/CV-parser/verifysum_run.py      # 어느 폴더에서든
# 또는 CV-parser 폴더 안에서:  python3 -m verifysum
# → http://127.0.0.1:8795
```

`No module named verifysum` 이 나오면 CV-parser 폴더 밖에서 `-m` 으로 실행한 것이다.
`verifysum_run.py` 로 실행하면 된다.

설정은 `.env` 에 적어 두면 된다 (지원자 관리와 같은 파일). 다른 PC 에서 안 열리면 서버 방화벽에서
8795 포트를 열어야 한다 (지원자 관리 8600 을 연 것과 같은 방법).

| 환경 변수 | 뜻 | 기본 |
|---|---|---|
| `VERIFYSUM_PORT` | 포트 | 8795 |
| `VERIFYSUM_HOST` | 이 PC 에서만 쓰려면 `127.0.0.1` | 0.0.0.0 (다른 PC 에서도 열림) |
| `VERIFYSUM_PASSWORD` | 있으면 브라우저가 비밀번호를 묻는다 | 없음 |
| `VERIFYSUM_WORKERS` | 동시에 LLM 에 보낼 사람 수 | 2 |
| `VERIFYSUM_LLM_TIMEOUT` | LLM 한 번 기다리는 시간(초) | 600 |
| `VERIFYSUM_RETRIES` | 타임아웃·연결 끊김·서버 5xx 때 알아서 다시 하는 횟수 | 3 |
| `VERIFYSUM_DATA_DIR` | 예시·결과 파일 둘 곳 | `~/.cvtool/verifysum` |

## 쓰는 순서

1. **예시로 방식 익히기** — 예시 검증 파일 · 예시 1장 결과 · 예시 요약 결과(같은 사람이면 가장 좋다)를 넣고
   `분석하기`. 항목 이름, 줄인 분량, 요약 칸 너비·글꼴을 읽고, LLM 이 예시를 나란히 보고 **작성 지침**을 쓴다.
   지침은 화면에서 고쳐 저장할 수 있다.
2. **후보자 파일 넣기** — 검증 파일을 한꺼번에 골라 `결과 만들기`. 파일 이름 순서대로 결과에 들어간다.
3. **받기** — 끝나면 두 파일을 내려받는다. `확인필요` 로 표시된 사람은 메모를 보고 워드에서 한 번 확인한다.

## 어떻게 맞추나

- **모양**: 예시 결과 파일 두 개를 틀로 쓴다. 문단·표 XML 을 복사해 글만 바꾸므로 글꼴·칸 너비·테두리가 예시와 같다.
- **제목·소속·항목명·결과(추천)**: LLM 에 맡기지 않고 원본에서 그대로 가져온다.
- **요약 칸 두 줄**: 칸 너비와 글자 크기로 줄 수를 직접 센다(한글 1칸, 영문·숫자 반 칸, 띄어쓰기에서만 줄바꿈 —
  워드보다 보수적). 넘으면 LLM 에 다시 쓰게 하고, 그래도 넘으면 띄어쓰기 단위로 잘라 **두 줄을 지킨다**(확인필요 표시).
- **칸 글 모양**: LLM 에는 내용 덩어리만 받고 줄 맞춤은 코드가 한다.
  1장 검증 의견은 덩어리마다 `- ` 로 시작하고, 넘어가는 줄은 띄어쓰기 두 칸으로 글자 시작을 맞추며,
  덩어리 사이만 간격을 벌린다. 요약 칸은 작은 점(`· `, 예시에서 읽음)으로 시작하고 점은 줄 맨 앞에만 —
  점 두 개면 각각 한 줄. 표 줄 높이는 내용에 맞춘다(예시의 고정 높이는 뺀다).
- **작성자 줄**: 원본 검증 자료의 표 밑 작성자 문단을 모양 그대로 1장 결과에 옮긴다.
- **1장**: 예시 1장 표가 차지한 높이를 한 쪽 기준으로 삼아, 넘으면 긴 항목을 줄이게 한다. 그래도 넘으면 확인필요 표시.
- 후보자 원본 파일은 디스크에 저장하지 않는다.

## 실패했을 때 · 지난 결과

- LLM 이 타임아웃 · 연결 끊김 · 서버 바쁨(429/5xx)이면 5초 → 20초 → 60초 쉬고 알아서 다시 부른다 (`VERIFYSUM_RETRIES`).
- 그래도 안 되면 그 사람만 '실패'. 진행 표의 **실패한 N명 다시 하기** / **이 사람 다시** 로 그 사람만 다시 돌리고 결과 파일을 새로 만든다.
  원본은 메모리에만 있으므로 프로그램을 껐다 켜면 파일을 다시 넣어야 한다.
- 결과는 돌릴 때마다 `<데이터>/결과/<날짜-시각>/` 에 1장 통합본 · 요약표 · 진행 표(결과.json)로 남는다. 화면 아래 **지난 결과** 에서 다시 받는다.
