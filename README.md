# cvtool — 지원자 CV 분석 툴

사내 온프레미스(폐쇄망) 워크스테이션용 CV 분석 도구입니다.
**기존 인사 문서 RAG 시스템과 완전히 분리**해서 운영합니다.

CV(PDF/docx/txt) 여러 개를 웹에서 업로드하면 → 로컬 LLM으로 구조화 추출 →
표로 확인하고 → **엑셀(.xlsx)로 내려받습니다.**

---

## 빠른 시작

```bash
git pull                                   # 코드 받기

cp .env.example .env && vi .env            # 비밀번호 2개 설정 (자동으로 읽힙니다)

python3 -m pytest -q                       # LLM 없이 되는 검증 (169개)
python3 -m cvtool.cli health               # vLLM / TEI 연결 확인
python3 -m cvtool.web.app                  # 웹 실행 -> http://서버IP:8600
```

`pip install` 없이 동작합니다. 웹·저장소·엑셀은 **표준 라이브러리만** 사용합니다
(폐쇄망에서 설치 실패 위험을 없애려고 openpyxl·FastAPI를 쓰지 않았습니다).
추출에만 `httpx`, `pydantic`이 필요하고, PDF/docx는 `pypdf`, `python-docx`가 있을 때만 됩니다.

## 설계 원칙

- **모델을 새로 올리지 않습니다.** GPU 여유가 ~20GB뿐이라 모델을 또 올리면 인사 RAG가
  OOM으로 죽습니다. 이미 떠 있는 서비스를 OpenAI 호환 API로 **호출만** 합니다.

  | 서비스 | 주소 | 모델 | 용도 |
  |---|---|---|---|
  | vLLM | `http://localhost:8000/v1` | `thinkingcap` | 구조화 추출 |
  | TEI 임베딩 | `http://localhost:8081` | KURE-v1 (1024차원) | JD↔CV 유사도 |
  | TEI 리랭커 | `http://localhost:8082` | bge-reranker-v2-m3 | 후보 정렬 |

- **저장소 분리.** 기존 Qdrant(6333)·Postgres(5432)는 인사 문서가 들어 있고 컬렉션 단위
  권한이 없어 붙기만 하면 전문이 노출됩니다. 지원자 데이터는 별도 sqlite 파일
  (`~/.cvtool/`)에 격리 저장하며, 기존 저장소에 **전혀 접속하지 않습니다.**

- **개인정보 보호.**
  - CV 원본은 `~/.cvtool/files/` 에 지원자_ID 이름으로 보관되고, 삭제·만료 시 함께 지워집니다.
  - 데이터 디렉터리 0700, DB 파일 0600 — 서버의 다른 계정이 못 읽습니다.
  - 보관 기간(기본 6개월)이 지나면 삭제 대상이 됩니다 (`store.purge_expired()`).
  - 벡터 DB에 넣을 때는 payload에 **지원자_ID만**, 개인정보는 넣지 않습니다.
  - CV 파일은 `.gitignore`로 커밋이 차단됩니다.
  - 외부 API 호출이 없습니다(폐쇄망, 전부 로컬).

- **시간대.** 서버 시계는 UTC입니다. 항상 `cvtool.timeutil.now_kst()`로
  **Asia/Seoul을 명시**합니다.

## 분석 방식 — 규칙 파싱을 쓰지 않습니다

CV는 정해진 양식이 없으므로 **본문을 정규식이나 규칙으로 파싱하지 않습니다.**
이름·날짜·학교를 위치나 패턴으로 뽑는 코드는 한 줄도 없습니다(테스트로 강제).

```
CV 파일 → 텍스트 → [1단계] 자유롭게 읽고 정리 → [2단계] 섹션별 JSON 강제 → 병합
```

**1단계 (읽기).** 스키마 없이 자유 서술로 CV를 읽고 정리하게 둡니다.
`guided_json`은 **첫 토큰부터** JSON 문법을 강제해서 추론 모델(`thinkingcap`)이
생각할 자리를 없앱니다. 읽는 동안에는 문법을 풀어줍니다.

**2단계 (구조화).** 1단계 정리 노트 + 원문을 함께 주고 4개 섹션
(기본/학력/연구/경력)으로 나눠 JSON을 받습니다. 출력 형식은 **세 겹으로** 요구합니다
— `guided_json` → `response_format` → 구조화 필드 없이 프롬프트 지시만.
**프롬프트에 스키마와 "JSON 객체 하나만 출력하라"는 지시가 항상 들어갑니다.**
서버가 `guided_json`을 400 없이 조용히 무시하면 모델은 JSON을 만들 이유가 없어
산문으로 답하는데, 그러면 모든 섹션이 실패합니다(실제로 겪었습니다). 섹션을 나누면 출력이
짧아져 잘리지 않고, 모델이 한 번에 한 가지에 집중합니다. 한 섹션이 실패해도
나머지는 살리고 `검토_필요`로 표시합니다.

CV 한 장당 LLM 호출은 **5회**(읽기 1 + 섹션 4)입니다. 느리면
`CVTOOL_TWO_STAGE=0`으로 끄면 4회가 되지만 정확도가 떨어집니다. **켜고 꺼서
비교해보세요.**

### LLM 출력은 그대로 믿지 않고 형식을 맞춥니다

프롬프트로 "YYYYMM 6자리"라고 해도 모델은 형식을 자주 어깁니다. 실제로 이런
값들이 섞여 나옵니다: `2019.03`, `2019-3`, `Mar 2019`, `2019년 3월`, `present`.

`cvtool/normalize.py` 가 이걸 약속한 형식으로 맞춥니다. **CV 본문을 파싱하는
것이 아니라 LLM 이 이미 뽑아준 짧은 값을 다듬는 것**입니다 — CV 를 읽고 판단하는
일은 전부 LLM 이 합니다.

- 연·월 → `YYYYMM` (연도만 알면 `YYYY00`)
- 생년월일 → `YYYYMMDD` (일자가 없으면 지어내지 않고 비움)
- 전화번호 → `010-1234-5678` (`+82` 는 `0` 으로 복원, 모르는 형태는 원문 유지)
- enum 목록 밖 값 → `불명` (엑셀 필터가 깨지지 않게)
- 셀 안 줄바꿈·탭 제거

무엇을 고쳤는지는 `검토_사유` 에 남습니다. **형식 보정이 자주 뜨면 프롬프트 문제**
이니 그 값을 알려주세요.

### 판단이 안 될 때는 찍지 않습니다

`현재_신분` 등의 enum에는 **`불명`이 들어 있습니다.** 이 값이 없으면
`guided_json`이 문법을 강제하는 탓에 모델이 판단이 안 서도 목록에서 하나를
억지로 고릅니다(그럴듯한 오답). `불명`이면 `검토_필요=Y`가 됩니다.

학회의 국내/해외 판별도 프롬프트에 목록을 박아두지 않았습니다. 모르면 `불명`으로
두고, **분류는 웹의 학회 관리 화면에서 사람이 합니다.**

## 엑셀 컬럼 (31개)

| 그룹 | 열 |
|---|---|
| 식별·기본 | `지원자_ID` `한글_이름` `영문_이름` `이름_추정여부` `생년월일` `전화번호` `이메일` |
| 현재 | `현재_신분` `현재_소속` `현재_소속_상세` `현재_지도교수` |
| 박사 | `박사_학교` `박사_전공` `박사_지도교수` `박사_시작` `박사_졸업` `박사_학위상태` |
| 석사 | `석사_학교` `석사_전공` `석사_지도교수` `석사_시작` `석사_졸업` |
| 학사 | `학사_학교` `학사_전공` `학사_시작` `학사_졸업` |
| 연구 | `1저자_해외논문_제출처` `연구분야_키워드` |
| 경력 | `경력_요약` |
| 검토 | `검토_필요` `검토_사유` |

- 날짜는 `YYYYMM`(생년월일만 `YYYYMMDD`), 없으면 빈칸.
- `현재_신분`: 포닥 / 박사 / 석박통합 / 석사 / 학사 / 타사재직 / 기타 / **불명**
- 전화번호·날짜는 **문자열 셀로 기록**되어 앞자리 0이 사라지거나 날짜로 바뀌지 않습니다.
- `원본_파일명`·`추출_일시`·`보관_만료일`은 엑셀에서 뺐지만 **DB에는 유지**됩니다
  (자동 삭제와 역추적에 필요합니다). 웹 화면에서는 파일별 처리 현황으로 확인됩니다.

### 석박통합 처리

석박사 통합과정은 **석사 학위를 따로 받지 않으므로** 이렇게 들어갑니다.

| 열 | 값 |
|---|---|
| `현재_신분` | `석박통합` |
| `박사_*` | 통합과정 정보 (`박사_시작` = **통합과정 입학년월**) |
| `석사_*` | 전부 빈칸 |
| `박사_학위상태` | `재학` 또는 `예정` |

`박사_시작`이 통합과정 입학 시점이라 일반 박사보다 기간이 길어 보이는데,
`현재_신분=석박통합`이 그 표시입니다. 통합과정 중 **석사만 취득하고 나온 경우**에는
석사 열을 채우고, 그때는 `검토_필요`로 표시해 사람이 확인하게 합니다.

## 지원자 관리

웹 첫 화면(`/`)이 관리 화면입니다.

| 하고 싶은 것 | 위치 |
|---|---|
| 지원자 목록 보기 | `/` — 표로 전체 표시 |
| **검색** | 상단 검색창 — 이름·소속·학교·이메일·파일명·ID |
| **검토 필요만 보기** | 검색창 옆 체크박스 |
| **상세 보기** | 각 행의 `상세` 링크 — 전체 항목 + 관리 정보 |
| **한 명 삭제** | 상세 화면의 `삭제` 버튼 |
| **여러 명 삭제** | 목록에서 체크 후 `선택 삭제` |
| **만료분 일괄 삭제** | 만료 건이 있으면 상단에 경고와 버튼이 뜸 |
| **원본 다운로드** | 상세 화면 — 실제 이력서 파일 |
| **다시 분석** | 상세 화면 — 보관된 원본에서 재추출 |
| 엑셀 받기 | `엑셀(.xlsx) 다운로드` |

삭제는 **되돌릴 수 없고** 확인창이 뜹니다. 목록에는 `보관만료` 열이 함께 나옵니다.

`업로드 처리 현황`은 메모리에만 있는 진행 표시입니다. `현황 지우기`는 그 목록만
비우며 **지원자 데이터는 지우지 않습니다.**

### 데이터가 저장되는 위치

전부 `~/.cvtool/` 아래입니다 (`CVTOOL_DATA_DIR` 로 변경 가능).

| 무엇 | 어디 | 남는가 |
|---|---|---|
| **CV 원본 파일** | `~/.cvtool/files/CV-XXXXXXXX.pdf` | ⭕ 보관 기간까지 |
| **추출 결과**(이름·연락처·이메일) | `~/.cvtool/candidates.db` | ⭕ 보관 기간까지 |
| CV 원문 텍스트 | `candidates.db` 의 `원문_텍스트` 열 | 기본 ❌ / `CVTOOL_STORE_CV_TEXT=1` 이면 ⭕ |
| 학회·저널 목록 | `~/.cvtool/venues.db` | ⭕ |
| 업로드 처리 현황 | 메모리만 | ❌ 재시작하면 사라짐 |

**원본 파일명은 지원자_ID 로 바뀝니다** (`이력서_홍길동.pdf` → `CV-8A1F7854.pdf`).
파일명 자체가 개인정보가 되는 것을 막기 위해서입니다. 다운로드할 때는 원래
파일명으로 되돌려 내려받습니다.

**삭제하면 원본도 함께 지워집니다.** 단건 삭제·일괄 삭제·보관기간 만료 삭제 모두
DB 행과 원본 파일을 같이 지웁니다. 둘이 어긋나면 개인정보가 남기 때문입니다.
DB 에 행이 없는 원본(추출 실패·크래시)은 다음 기동 때 자동으로 삭제됩니다.

**파일 권한:** 디렉터리는 `0700`, DB·원본 파일은 `0600` 으로 잠급니다. 개인정보가
든 파일을 서버의 다른 계정이 읽으면 웹 로그인을 걸어둔 의미가 없기 때문입니다.
기동 시 권한을 다시 조이고, 열려 있으면 경고를 출력합니다.

> 삭제는 `unlink` 이며 디스크 안전 삭제(shred)가 아닙니다. 디스크를 폐기하거나
> 반출할 때는 별도 조치가 필요합니다.

### 원본 열람과 재분석

상세 화면에서 **원본 다운로드**로 실제 이력서를 열어볼 수 있습니다. 추출 결과가
미심쩍을 때 원문과 대조하거나 면접관에게 보여줄 때 씁니다.

**다시 분석**은 보관된 원본에서 텍스트를 새로 뽑아 재추출합니다. 그래서 PDF 파서나
프롬프트를 개선하면 **재업로드 없이 반영**됩니다. 결과는 같은 지원자_ID 에
덮어쓰므로 행이 늘어나지 않습니다.

## 학회·저널 등급 관리

`1저자_해외논문_제출처` 열은 **해외 학회/저널만** 담습니다. 판별은 웹에서 관리합니다.

1. CV에서 발견된 제출처 중 목록에 없는 것은 **자동으로 `미분류`로 등록**됩니다.
2. `학회·저널 관리` 화면에서 등급(최우수/우수/일반/제외), 유형(학회/저널), 국내/해외를 지정합니다.
3. **담당자가 정한 값이 LLM 추측을 덮어씁니다.** 사람 판별이 항상 우선입니다.
4. 미분류가 남아 있으면 해당 지원자는 `검토_필요=Y`로 표시됩니다.

표기 흔들림은 정규화로 묶습니다 — `NeurIPS`, `neurips`, `Proc. of NeurIPS 2023`은
같은 항목입니다. 약어가 달라 안 묶이는 경우(`NIPS` ↔ `Neural Information...`)는
`merge()`로 합칠 수 있습니다.

## 문제가 생기면

### 추출이 실패할 때

**LLM 응답 원본을 그대로 보여주는 진단 스크립트**를 쓰세요. 아무것도 자르지 않습니다.

```bash
python3 tools/diagnose_llm.py tests/sample_cv.txt
```

`finish_reason`, `reasoning_content` 유무, `content` 원본을 전부 출력하고
guided_json / response_format / 스키마 없음 세 방식을 비교합니다.

| 증상 | 원인 |
|---|---|
| 로그인 화면에서 `CVTOOL_WEB_PASSWORD 가 비어 있습니다` | `.env` 를 못 읽었거나 그 안에 값이 없습니다. **서버 콘솔 첫 줄**에 어느 `.env` 를 읽었는지 찍히니 그걸 확인하세요. `.env.example` 을 고친 건 아닌지도 확인하세요 |
| `출력이 토큰 한도에 걸려 잘렸습니다` | `CVTOOL_LLM_MAX_TOKENS` 를 늘리세요 |
| `JSON 파싱 실패` / `구조화 출력 실패` | 모델 응답을 `tools/check_json.py` 에 넣어보세요. 파서가 어디서 막히는지 단계별로 보여줍니다 |
| 처리 현황에 `텍스트를 추출하지 못했습니다` | 스캔 PDF입니다. OCR이 필요합니다 |
| `ImportError: pypdf` | PDF 라이브러리 미설치 |

### 여러 장으로 실제 품질을 재보세요

한 장이 잘 나왔다고 "웬만한 CV 에 대응된다"고 볼 수 없습니다. 폴더에 CV 를 모아두고
돌리면 어떤 항목이 자주 비는지, 어떤 파일이 실패하는지 한눈에 나옵니다.

```bash
python3 tools/batch_check.py ~/cv_samples
```

결과를 DB 에 저장하지 않는 순수 점검용입니다. 형식(PDF/docx)·길이·언어가 다른
CV 를 섞어서 넣으세요. **`자주 비는 항목`이 곧 다음에 손볼 곳**입니다.

### 추출 품질이 나쁠 때 — 어느 단계가 문제인지 먼저 보세요

추측하지 말고 단계별 출력을 확인하세요. 아무것도 자르지 않고 전 과정을 찍습니다.

```bash
python3 tools/trace_extract.py 이력서.pdf --save trace.txt
python3 tools/trace_extract.py 이력서.pdf --no-two-stage   # 1단계 끄고 비교
```

| 단계 | 여기가 이상하면 |
|---|---|
| `[0] 추출 텍스트` | 파서 문제. 프롬프트를 고쳐도 안 좋아집니다 |
| `[1] 읽기 단계` | 모델이 CV 를 이해 못 함. **여기가 틀리면 뒤는 전부 틀립니다** |
| `[2] 섹션별 JSON` | 이해는 했는데 항목에 잘못 넣음 → 프롬프트 문제 |
| `[3] 정규화 후` | 형식 보정이 값을 망가뜨림 |

`[요약]` 의 빈 항목 목록과 검토 사유를 보면 무엇이 안 뽑혔는지 바로 보입니다.

### 입력 텍스트 자체를 의심할 때

**입력 텍스트가 깨져 있으면 프롬프트를 아무리 손봐도 좋아지지 않습니다.**
PDF를 텍스트로 바꾼 결과를 직접 눈으로 보세요.

```bash
python3 -c "
from cvtool.ingestion.parsers import extract_text
print(extract_text('문제의이력서.pdf')[:3000])
"
```

사람이 읽어서 말이 안 되면 원인은 여기입니다. 2단 편집·표가 많은 학술 CV에서
흔합니다. PDF는 `pypdf`의 **layout 모드**로 원본 배치를 살려 뽑고, 실패하면
기본 모드로 물러납니다(pypdf 4.0+ 필요).

그래도 깨지면 스캔 PDF이거나 레이아웃이 특수한 경우입니다. `/opt/data-gov`의
이미지/OCR 파서를 참고해야 합니다.

| 확인할 것 | 뜻 |
|---|---|
| 텍스트가 뒤죽박죽 | PDF 추출 문제 — 위 참고 |
| `검토_사유`에 `잘랐습니다` | CV가 길어 뒤쪽(보통 논문 목록)이 누락됨. `CVTOOL_MAX_INPUT_CHARS` 를 늘리세요 |
| 논문이 통째로 비어 있음 | 저자 순서를 못 읽은 경우. 지원자 이름을 프롬프트에 넣어 대조하지만, 굵기 표시는 텍스트에서 사라집니다 |
| `현재_신분=불명` | 모델이 판단을 못 한 것. 찍는 것보다 낫습니다 |

### 알려진 주의점

- **이름 추정은 신뢰하지 마세요.** 로마자에서 한글 복원은 원리적으로 불가능합니다
  (`Minjun Kim` → 김민준? 김민중?). 추정한 경우 `이름_추정여부`에 표시되고
  `검토_필요=Y`가 됩니다. **면접 안내 전에 반드시 원문과 대조하세요.**
- 성별·나이·사진·가족사항은 일부러 넣지 않았습니다. 채용절차법상 직무와 무관한
  개인정보 수집이 제한됩니다. 필요하면 인사/법무 확인 후 추가하세요.

  2줄 결과, xlsx 다운로드

  물러나도록 해뒀지만, 실제 CV 로 확인이 필요합니다
