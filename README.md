# cvtool — 지원자 관리 (CV 구조화 추출 + 채용 현황)

사내 온프레미스(폐쇄망) 워크스테이션용 지원자 관리 도구입니다. CV 를 구조화해 뽑고, 그 지원자들의 채용 진행 상태까지 한 곳에서 봅니다.
**기존 인사 문서 RAG 시스템과 완전히 분리**해서 운영합니다.

CV(PDF/docx/txt) 여러 개를 웹에서 업로드하면 → 로컬 LLM으로 구조화 추출 →
표로 확인하고 → **엑셀(.xlsx)로 내려받습니다.**

---

## 빠른 시작

```bash
git pull                                   # 코드 받기

pip install -r requirements.txt            # 필요한 패키지 설치
python3 -m cvtool.cli deps                 # 설치 확인 (뭐가 없는지 알려줍니다)

cp .env.example .env && vi .env            # 비밀번호 2개 설정 (자동으로 읽힙니다)

python3 -m pytest -q                       # LLM 없이 되는 검증 (578개)
python3 -m cvtool.cli health               # vLLM / TEI 연결 확인
python3 -m cvtool.web.app                  # 웹 실행 -> http://서버IP:8600
```

필요한 패키지는 **4개뿐**입니다 (`httpx`, `pydantic`, `pypdf`, `python-docx`).
웹 서버·엑셀 출력·저장소는 **표준 라이브러리만** 써서 FastAPI·openpyxl·psycopg·
qdrant-client 가 필요 없습니다. 테스트까지 하려면 `requirements-dev.txt` 를 쓰세요.

`python3 -m cvtool.cli deps` 가 무엇이 없는지, **설치는 됐는데 깨졌는지**까지
구분해서 알려줍니다.

## 설계 원칙

- **모델을 새로 올리지 않습니다.** GPU 여유가 ~20GB뿐이라 모델을 또 올리면 인사 RAG가
  OOM으로 죽습니다. 이미 떠 있는 서비스를 OpenAI 호환 API로 **호출만** 합니다.

  | 서비스 | 주소 | 모델 | 용도 |
  |---|---|---|---|
  | vLLM | `http://localhost:8000/v1` | `thinkingcap` | 구조화 추출 |
  | TEI 임베딩 | `http://localhost:8081` | KURE-v1 (1024차원) | JD↔CV 유사도 |
  | TEI 리랭커 | `http://localhost:8082` | bge-reranker-v2-m3 | 후보 정렬 |

- **저장소 분리.** 기존 Qdrant(6333)·Postgres(5432)는 인사 문서가 들어 있고 컬렉션 단위
  권한이 없어 붙기만 하면 전문이 노출됩니다. 지원자 데이터는 별도 sqlite 파일
  (`~/.cvtool/`)에 격리 저장하며, 기존 저장소에 **전혀 접속하지 않습니다.**

- **개인정보 보호.**
  - CV 원본은 `~/.cvtool/files/` 에 지원자_ID 이름으로 보관되고, 삭제·만료 시 함께 지워집니다.
  - 데이터 디렉터리 0700, DB 파일 0600 — 서버의 다른 계정이 못 읽습니다.
  - 보관 기간(기본 6개월)이 지나면 삭제 대상이 됩니다 (`store.purge_expired()`).
  - 벡터 DB에 넣을 때는 payload에 **지원자_ID만**, 개인정보는 넣지 않습니다.
  - CV 파일은 `.gitignore`로 커밋이 차단됩니다.
  - 외부 API 호출이 없습니다(폐쇄망, 전부 로컬).

- **시간대.** 서버 시계는 UTC입니다. 항상 `cvtool.timeutil.now_kst()`로
  **Asia/Seoul을 명시**합니다.

## 분석 방식 — 규칙 파싱을 쓰지 않습니다

CV는 정해진 양식이 없으므로 **본문을 정규식이나 규칙으로 파싱하지 않습니다.**
이름·날짜·학교를 위치나 패턴으로 뽑는 코드는 한 줄도 없습니다(테스트로 강제).

```
CV 파일 → 텍스트 → [1단계] 자유롭게 읽고 정리 → [2단계] 섹션별 JSON 강제 → 병합
```

**1단계 (읽기).** 스키마 없이 자유 서술로 CV를 읽고 정리하게 둡니다.
`guided_json`은 **첫 토큰부터** JSON 문법을 강제해서 추론 모델(`thinkingcap`)이
생각할 자리를 없앱니다. 읽는 동안에는 문법을 풀어줍니다.

**2단계 (구조화).** 1단계 정리 노트 + 원문을 함께 주고 4개 섹션
(기본/학력/연구/경력)으로 나눠 JSON을 받습니다. 출력 형식은 **세 겹으로** 요구합니다
— `guided_json` → `response_format` → 구조화 필드 없이 프롬프트 지시만.
**프롬프트에 스키마와 "JSON 객체 하나만 출력하라"는 지시가 항상 들어갑니다.**
서버가 `guided_json`을 400 없이 조용히 무시하면 모델은 JSON을 만들 이유가 없어
산문으로 답하는데, 그러면 모든 섹션이 실패합니다(실제로 겪었습니다). 섹션을 나누면 출력이
짧아져 잘리지 않고, 모델이 한 번에 한 가지에 집중합니다. 한 섹션이 실패해도
나머지는 살리고 `검토_필요`로 표시합니다.

CV 한 장당 LLM 호출은 **5회**(읽기 1 + 섹션 4)입니다. 느리면
`CVTOOL_TWO_STAGE=0`으로 끄면 4회가 되지만 정확도가 떨어집니다. **켜고 꺼서
비교해보세요.**

### LLM 출력은 그대로 믿지 않고 형식을 맞춥니다

프롬프트로 "YYYYMM 6자리"라고 해도 모델은 형식을 자주 어깁니다. 실제로 이런
값들이 섞여 나옵니다: `2019.03`, `2019-3`, `Mar 2019`, `2019년 3월`, `present`.

`cvtool/normalize.py` 가 이걸 약속한 형식으로 맞춥니다. **CV 본문을 파싱하는
것이 아니라 LLM 이 이미 뽑아준 짧은 값을 다듬는 것**입니다 — CV 를 읽고 판단하는
일은 전부 LLM 이 합니다.

- 연·월 → `YYYYMM` (연도만 알면 `YYYY00`)
- 생년월일 → `YYYYMMDD` (일자가 없으면 지어내지 않고 비움)
- 전화번호 → `010-1234-5678` (`+82` 는 `0` 으로 복원, 모르는 형태는 원문 유지)
- enum 목록 밖 값 → `불명` (엑셀 필터가 깨지지 않게)
- 셀 안 줄바꿈·탭 제거

무엇을 고쳤는지는 `검토_사유` 에 남습니다. **형식 보정이 자주 뜨면 프롬프트 문제**
이니 그 값을 알려주세요.

### 판단이 안 될 때는 찍지 않습니다

`현재_신분` 등의 enum에는 **`불명`이 들어 있습니다.** 이 값이 없으면
`guided_json`이 문법을 강제하는 탓에 모델이 판단이 안 서도 목록에서 하나를
억지로 고릅니다(그럴듯한 오답). `불명`이면 `검토_필요=Y`가 됩니다.

학회의 국내/해외 판별도 프롬프트에 목록을 박아두지 않았습니다. 모르면 `불명`으로
두고, **분류는 웹의 학회 관리 화면에서 사람이 합니다.**

## 엑셀 컬럼 (30개)

| 그룹 | 열 |
|---|---|
| 식별·기본 | `한글_이름` `영문_이름` `이름_추정여부` `생년월일` `전화번호` `이메일` |
| 현재 | `현재_신분` `현재_소속` `현재_소속_상세` `현재_지도교수` |
| 박사 | `박사_학교` `박사_전공` `박사_지도교수` `박사_시작` `박사_졸업` `박사_학위상태` |
| 석사 | `석사_학교` `석사_전공` `석사_지도교수` `석사_시작` `석사_졸업` |
| 학사 | `학사_학교` `학사_전공` `학사_시작` `학사_졸업` |
| 연구 | `1저자_해외논문_제출처` `연구분야_키워드` |
| 경력 | `경력_요약` |
| 검토 | `검토_필요` `검토_사유` |

- 날짜는 `YYYYMM`(생년월일만 `YYYYMMDD`), 없으면 빈칸.
- `현재_신분`: 포닥 / 박사 / 석박통합 / 석사 / 학사 / 타사재직 / 기타 / **불명**
- 전화번호·날짜는 **문자열 셀로 기록**되어 앞자리 0이 사라지거나 날짜로 바뀌지 않습니다.
- 국가번호로 적힌 번호는 국내 형식으로 바뀝니다: `+82 10-1234-5678` → `010-1234-5678`,
  `+82 2 880 1234` → `02-880-1234`. **한국 번호가 아니면(`+1 …`) 손대지 않습니다.**
- `지원자_ID` 는 내부 키라서 표·엑셀에 나오지 않습니다 (레코드에는 그대로 있습니다).
- `원본_파일명`·`추출_일시`·`보관_만료일`은 엑셀에서 뺐지만 **DB에는 유지**됩니다
  (자동 삭제와 역추적에 필요합니다). 웹 화면에서는 파일별 처리 현황으로 확인됩니다.

### 석박통합 처리

석박사 통합과정은 **석사 학위를 따로 받지 않으므로** 이렇게 들어갑니다.

| 열 | 값 |
|---|---|
| `현재_신분` | `석박통합` |
| `박사_*` | 통합과정 정보 (`박사_시작` = **통합과정 입학년월**) |
| `석사_*` | 전부 빈칸 |
| `박사_학위상태` | `재학` 또는 `예정` |

`박사_시작`이 통합과정 입학 시점이라 일반 박사보다 기간이 길어 보이는데,
`현재_신분=석박통합`이 그 표시입니다. 통합과정 중 **석사만 취득하고 나온 경우**에는
석사 열을 채우고, 그때는 `검토_필요`로 표시해 사람이 확인하게 합니다.

## 채용 현황 관리

`채용 현황` 탭에서 지원자별 진행 상태를 관리합니다. **지원자 DB는 하나**이고,
여기에는 채용 진행에 관한 것만 붙습니다.

```
서류 검토 → 전화 면접 → 기술 면접 → HR 면접      (순서 고정)
각 단계: 진행중 / 합격 / 불합격 / 보류           (빈칸 = 아직 시작 안 함)
```

- **저장 버튼은 맨 위 하나뿐입니다.** 여러 사람 상태를 바꾸고 한 번에 저장합니다.
  고친 칸은 노랗게 표시되고, 저장하면 무엇이 바뀌었는지 화면 위에 뜹니다.
- **부서와 과제가 각각 열입니다.** 부서를 고르면 과제 칸이 그 부서 것으로 바뀝니다
  (다른 부서 과제는 자동으로 풀립니다).
- `비고` 칸에 자유롭게 메모할 수 있습니다.
- `최종상태` 열이 지금 어디까지 왔는지 한 줄로 보여줍니다
  (`전화 면접 진행중`, `서류 검토 불합격`, `최종 합격` 등).
- **지원자 정보 열은 여기서 고칠 수 없습니다.** 채용 상태를 보는 화면에서 지원자
  정보까지 고쳐지면 실수로 덮어쓰기 쉬워서, 보기만 됩니다. 고칠 일이 있으면
  지원자 목록이나 상세 화면에서 합니다.
- `엑셀(.xlsx) 다운로드` 로 지금 보이는 표 그대로 받을 수 있습니다.

### 정렬

기본 정렬은 진행이 많이 된 순서이고, **불합격자는 항상 맨 아래**, 보류는 진행중보다
아래입니다. 열 제목을 누르면 그 열로 다시 정렬됩니다.

### 표에 보일 열 (관리자)

`표 열 구성`에서 지원자 DB의 모든 열 중 원하는 것만 골라 순서까지 정합니다.
관리자만 바꿀 수 있습니다.

## 표 항목 — 열 추가와 열 설정

`표 항목` 화면에서 **이 시스템이 아는 모든 열을 한 자리에서** 봅니다.
**관리자만** 바꿀 수 있습니다. 열은 네 묶음으로 나눠 보여줍니다.

| 묶음 | 무엇 | 어디에 쓰이나 |
|---|---|---|
| **지원자 정보** | CV 에서 뽑는 열 (이름·학력·논문·경력…) | 지원자 목록 · 엑셀 |
| **관리 정보** | `등록년도` `등록일시` `원본_파일명` `보관_만료일` | 지원자 목록 · 엑셀 (보기 전용) |
| **채용 현황** | `부서` `과제` 단계별 상태 `최종상태` `비고` | 채용 현황 표 · 채용 엑셀 |

**직접 추가한 열도 어느 묶음인지 고릅니다.** 열을 만들 때 `구분` 을 `지원자 정보`
로 하면 지원자 목록·엑셀에, `채용 현황` 으로 하면 채용 현황 표에 붙습니다.
채용 현황으로 만든 열은 **채용 현황 표에서 바로 고칩니다** (지원자 정보 열은
거기서 못 고칩니다). 구분은 나중에 바꿀 수 있고, 바꾸면 열이 표를 옮겨 갑니다.

### 고칠 수 있는 것과 없는 것

경계는 하나입니다 — **형식 검사와 추출 스키마.**

| | 고칠 수 있나 | 왜 |
|---|---|---|
| 모든 열의 **표에 보일 이름 · 순서 · 숨김** | ✅ | 값에 손대지 않습니다 |
| **단계 상태 목록** (`서류 검토` 등에서 고르는 값) | ✅ | 추출 스키마와 무관합니다 |
| **추가한 열**의 이름 · 구분 · 선택지 · 유형 | ✅ | 내가 만든 열입니다 |
| **지원자 정보 열**의 선택지 (`현재_신분` 등) | ❌ | guided_json 추출 스키마에 그대로 들어갑니다 |
| **지원자 정보 열**의 입력 형식 | ❌ | 형식 검사가 걸려 있어 이미 든 값과 어긋납니다 |

안전장치가 셋 있습니다.

- **단계 상태**에서 빈칸·`합격`·`불합격` 은 뺄 수 없습니다. 최종상태·탈락
  판정·정렬이 이 값을 보고 돌아갑니다. 나머지(`진행중` `보류` …)는 자유롭게
  바꾸고 새로 넣을 수 있습니다. 네 단계가 같은 목록을 씁니다.
- **쓰고 있는 값은 못 뺍니다.** 그 상태인 지원자가 있으면 거부하고 누구인지
  알려줍니다. 먼저 그 사람들 상태를 바꿔야 합니다. 추가한 열의 선택지도 같습니다.
- **유형 변경**은 이미 든 값이 새 유형에서도 전부 통과할 때만 됩니다.
  `텍스트`→`숫자` 로 바꾸려는데 `아주 좋음` 이 들어 있으면 거부합니다.

**이름을 바꾸면 값도 따라옵니다** — 들어 있던 값과 열 설정을 같이 옮깁니다.

### 모든 열에 할 수 있는 것

| | |
|---|---|
| **표에 보일 이름** | `영문_이름` → `English Name` 처럼 머리글만 바꿉니다 |
| **순서** | 작은 번호가 앞. 비우면 원래 자리 — 한 열만 옮겨도 나머지는 그대로 |
| **숨김** | 표·엑셀에서 뺍니다 (값은 지워지지 않습니다) |

바꾼 이름과 순서는 **화면과 엑셀에 함께** 나갑니다 — 지원자 목록·지원자 엑셀,
그리고 채용 현황 표·채용 엑셀까지. 여러 줄을 고치고 맨 위 `고친 내용 저장` 을
한 번 누릅니다.

> **관리 정보 열은 처음에 접혀 있습니다.** `등록년도` 만 보이고
> `등록일시` `원본_파일명` `보관_만료일` 은 숨김입니다. 표가 넓어지기만 하고
> 평소엔 안 보기 때문입니다. 필요하면 여기서 숨김을 풀면 바로 표에 나옵니다.
> 값은 자동으로 기록되고 표에서는 **고칠 수 없습니다** (등록년도는 지원자 상세
> 화면에서 고칩니다).

> **채용 현황 표에 어떤 열을 쓸지**는 `채용 현황` → `표 열 구성` 에서 고릅니다.
> 여기 `표 항목` 에서는 그 열의 **이름·순서·숨김**을 정합니다. 아직 고르지
> 않은 열에는 `(지금 표에 없음)` 이라고 표시됩니다.

> 기본 열의 **입력 형식은 바꾸지 않습니다.** 형식 검사와 추출 스키마가 그 열에
> 걸려 있어서 여기서 바꾸면 이미 들어 있는 값과 어긋납니다. 안 쓰는 열은
> **숨김**으로 두세요. 삭제는 추가한 열만 됩니다.

### 열 추가

새로 만든 열의 유형에 따라 입력칸과 형식 검사가 달라집니다.

| 유형 | 입력 방식 | 형식 검사 |
|---|---|---|
| **텍스트** | 자유 입력 | 없음 |
| **선택** | 드롭다운 | 등록한 선택지 밖의 값은 저장 거부 |
| **연월** | `202603` 6자리 | 6자리 숫자 + 월 01~12 아니면 거부 |
| **숫자** | 정수 | 숫자가 아니면 거부 |

- 값은 **사람이 채웁니다.** LLM이 자동으로 채우지 않습니다 (없는 항목을 지어내지
  않게 하기 위해서입니다).
- 추가한 열은 **지원자 상세 화면 · 엑셀 출력 · 채용 현황 표 열 구성**에 모두
  나타납니다. `구분` 이 `채용 현황` 이면 지원자 목록에서는 빠지고 채용 현황
  표에서 **바로 고칠 수 있게** 나옵니다.
- 기본 열과 같은 이름은 만들 수 없습니다 (`이미 있는 기본 열입니다`).
- 열을 삭제하면 **거기 들어있던 모든 지원자의 값이 함께 지워집니다.** 확인창이
  한 번 뜹니다.
- 지원자를 삭제하면 그 지원자의 사용자 정의 값도 같이 지워집니다.

### 부서·과제 이름 수정

`부서·과제` 화면에서 부서명과 과제명을 **나중에 바꿀 수 있습니다.** 이름만 바뀌고
배정된 계정·지원자 연결은 그대로 유지됩니다. 같은 이름이 이미 있으면 거부합니다
(과제는 같은 부서 안에서만 중복을 봅니다). 과제 초대암호도 여기서 다시 걸거나
지울 수 있습니다.

## 연구 과제 매칭

회사 연구 과제를 정리해둔 JSON 을 읽어, 지원자가 **어느 과제와 잘 맞는지 점수와
판단 사유**를 냅니다. CV 를 분석하면 자동으로 함께 돌아갑니다.

```
88점 [매우 적합]  차세대 반도체 식각 공정 개발
     사유: 플라즈마 식각 공정 경험이 과제 주제와 그대로 맞습니다.
           다만 고종횡비 패턴 경험은 CV 에 없습니다.
     근거: 플라즈마 식각 · 식각 공정개발 3년
35점 [낮음]      AI 기반 공정 이상 탐지
     사유: 머신러닝 경력이 CV 에 없습니다.
```

- 지원자 **상세 화면**에 과제별 순위·점수·사유가 붙고, **`과제 매칭` 탭**에서
  지원자별 상위 과제를 한눈에 봅니다.
- **모든 과제와 비교합니다.** 상세 화면에는 상위 3개를 펼쳐 보이고 나머지는
  접어 둡니다 (`CVTOOL_MATCH_SHOW`).
- **사유가 핵심입니다.** 점수만 있으면 믿을 수가 없습니다. 무엇이 겹치고 무엇이
  부족한지 함께 쓰게 하고, **근거는 CV 에 적힌 표현을 그대로 인용**하게 합니다.
- 목록에 없는 과제를 지어내면 **버립니다.**
- 판단에 지원자 **이름·연락처는 넣지 않습니다.** 필요 없고, 넣으면 엉뚱한 판단의
  여지만 생깁니다.

### 과제 파일 경로 — `.env`

```
CVTOOL_PROJECTS_JSON=../과제정보/과제.json
```

**상대경로는 `CV-parser` 폴더 기준**입니다. `cd ../과제정보` 로 갈 수 있는 곳이면
위처럼 그대로 적으면 됩니다. 헷갈리면 절대경로가 확실합니다:

```
CVTOOL_PROJECTS_JSON=/home/사용자/과제정보/과제.json
```

`과제 매칭` 화면 맨 위에 **실제로 어느 파일을 읽었는지**와 몇 개를 읽었는지가
나옵니다. 못 읽으면 이유(파일 없음 / JSON 형식 오류 몇 번째 줄 / 이름 필드 못 찾음)를
그대로 보여줍니다. 파일을 고치면 다음 화면에서 자동으로 다시 읽습니다.

### 과제 파일 다듬기 — 필요한 것만 골라 씁니다

원본 과제 파일에는 매칭과 상관없는 항목이 많습니다(작성자·문서버전·보안등급·예산…).
그대로 LLM 에 밀어 넣으면 프롬프트만 길어지고 판단이 흐려집니다.

`과제 매칭` → **`과제 파일 다듬기`** 에서 한 번 골라 두면, 고른 것만 담긴 파일을
따로 만들고 **매칭은 그 파일을 씁니다. 원본은 건드리지 않습니다.**

1. **남길 정보 고르기** — 원본에 있는 필드가 전부 나옵니다. 각 필드마다 **얼마나
   채워져 있는지(예: 3/4, 75%)와 예시 값**이 같이 보여서, 비어 있거나 상관없는
   필드를 바로 골라낼 수 있습니다. 과제명은 없으면 과제를 알아볼 수 없으므로
   항상 남습니다.
2. **남길 과제 고르기** — 부서·과제명·키워드·내용을 보고 체크합니다.
   (총무팀 사옥 리모델링 같은 건 빼면 됩니다.)
3. **저장** — `~/.cvtool/과제_선별.json` 에 저장되고, 이후 매칭은 이 파일을 씁니다.

- 다시 들어가면 **지금 고른 상태가 그대로 체크**되어 있어 조금씩 고쳐 나갈 수 있습니다.
- `다듬은 파일 지우기` 를 누르면 다시 원본을 씁니다.
- `과제 매칭` 화면 맨 위에 지금 **원본을 쓰는지 다듬은 파일을 쓰는지** 표시됩니다.
- 저장 위치를 바꾸려면 `.env` 의 `CVTOOL_PROJECTS_CURATED` 를 씁니다.

> 다듬고 나면 이미 맞춰본 지원자는 옛 기준입니다. `과제 매칭` 에서
> **`이미 맞춰본 사람도 다시`** 를 켜고 다시 돌리세요.

### JSON 모양은 가리지 않습니다

흔한 형태를 모두 받습니다.

```json
[{"과제명": "...", "설명": "..."}]              목록
{"projects": [...]}                            감싼 목록
{"P-001": {"과제명": "...", ...}}               키가 과제 번호인 사전
```

필드 이름도 알아서 맞춥니다. 사내 파일에서 쓰는 이름은 **한글 이름을 붙여** LLM 에
넘깁니다.

| 원본 필드 | 쓰이는 곳 |
|---|---|
| `project_name` | 과제명 (**항상 남김**) |
| `dep_name` | 담당 부서 |
| `keywords_kr` `keywords_en` | 키워드 (**둘 다 합쳐서**) |
| `core_tech` `deliverable` `challenge` `background` `milestones` `expected_impact` | 설명에 `핵심 기술:` `산출물:` `기술적 난제:` `배경:` `마일스톤:` `기대 효과:` 로 |

**못 알아본 필드도 버리지 않고 설명에 이어 붙입니다** — 매칭에 쓸 정보를 임의로
버리면 안 되니까요. 정말 필요 없으면 위의 **다듬기**에서 빼세요.

### 어떻게 매기나 — 그리고 점수를 얼마나 믿어야 하나

**과제를 하나도 빠뜨리지 않고 전부 비교합니다.** 예전에는 임베딩으로 상위
몇 개만 골라 LLM 에 넣었는데(`CVTOOL_MATCH_TOP`), 그러면 나머지 과제는
**한 번도 보지 않고** 목록에서 사라졌습니다. 임베딩 서비스가 죽어 있으면
후보가 사실상 **파일 순서**가 돼서, 더 잘 맞는 과제가 통째로 빠졌습니다.
이 설정은 없앴습니다.

1. 임베딩(TEI)으로 과제를 지원자와 가까운 순으로 **정렬만** 합니다.
   좁히지는 않습니다. 임베딩이 죽어 있으면 정렬만 건너뛰고 그대로 갑니다.
2. 과제를 **`CVTOOL_MATCH_BATCH` 개씩(기본 5) 나눠서** LLM 에 넣습니다.
   한꺼번에 넣으면 답이 길어져 잘리고, 잘리면 결과가 통째로 사라집니다.
3. 한 묶음에서 모델이 **빠뜨린 과제는 한 번 더 묻습니다.** 그래도 답이
   없으면 그 과제는 **`미평가`** 로 남깁니다 — 조용히 빼면 사람이 비교된
   줄 압니다. 상세 화면 맨 위에 몇 개를 비교했고 몇 개가 미평가인지 씁니다.
4. 화면에는 상위 **`CVTOOL_MATCH_SHOW` 개(기본 3)** 를 펼쳐 보이고,
   나머지는 접어 둡니다. 과제가 3개보다 적으면 있는 만큼만 나옵니다.

#### 점수 눈금

점수를 그냥 매기게 하면 모델마다 CV 마다 기준이 달라집니다. 그래서 프롬프트에
**눈금을 박아 두고 그대로 따르게** 합니다. 화면에도 같은 눈금을 띄웁니다.

| 점수 | 뜻 |
|---|---|
| 90~100 | 과제의 핵심 기술·연구 주제가 지원자 경력과 그대로 일치. 바로 투입 가능 |
| 70~89 | 주요 기술이 상당 부분 겹침. 일부만 익히면 됨 |
| 50~69 | 인접 분야. 기반은 있으나 과제 핵심 기술 경험은 없음 |
| 30~49 | 전공·기초 소양만 겹침. 실제 경험 없음 |
| 0~29 | 접점이 거의 없음 |

> **점수는 측정값이 아니라 LLM 의 판단입니다.** 90점과 85점의 5점 차이에는
> 의미를 두지 마세요. 눈금은 구간(매우 적합/적합/인접 분야/…)을 맞추는
> 장치이지, 소수점까지 재는 자가 아닙니다. **믿을 것은 사유와 근거**입니다.
> 근거는 CV 에 적힌 표현을 그대로 인용하게 했으니, 인용이 실제 CV 에 있는지
> 보면 그 판단이 성립하는지 사람이 바로 확인할 수 있습니다.
>
> 함께 저장되는 **`유사도`**(임베딩 코사인)는 모델과 무관하게 **매번 같은 값이
> 나오는 참고치**입니다. 점수는 높은데 유사도가 낮거나 그 반대면 한 번 더
> 들여다볼 자리입니다.
>
> 같은 지원자를 다시 돌리면 점수가 조금 달라질 수 있습니다
> (`CVTOOL_LLM_TEMPERATURE` 기본 0 이라 대개는 같습니다).

**모델을 새로 올리지 않습니다.** 이미 떠 있는 vLLM·TEI 를 부르기만 합니다.

| 설정 | 뜻 |
|---|---|
| `CVTOOL_PROJECTS_JSON` | 과제 파일 경로 (비우면 기능 자체가 안 보임) |
| `CVTOOL_MATCH_BATCH` | 한 번에 물어볼 과제 수 (기본 5). 답이 자주 잘리면 줄이세요 |
| `CVTOOL_MATCH_SHOW` | 화면에 펼쳐 보일 상위 과제 수 (기본 3) |
| `CVTOOL_PROJECTS_CURATED` | 다듬은 파일 위치 (기본 `~/.cvtool/과제_선별.json`) |
| `CVTOOL_MATCH_AUTO` | CV 분석 뒤 자동 매칭 (기본 켜짐) |

과제 파일을 고쳤으면 `과제 매칭` 화면에서 **`안 맞춰본 지원자 맞춰보기`**(이미
맞춰본 사람도 다시 돌리는 체크박스 포함)로 다시 돌립니다.

## 메일 보내기

`메일` 탭에서 템플릿을 만들고 지원자에게 **한 사람씩 맞춰** 보냅니다.

### 템플릿 — 메일 쓰듯이 꾸며서

**글꼴 20종 · 크기 8~48pt · 글자색/배경색 · 굵게/기울임/밑줄/취소선 · 정렬 ·
글머리기호/번호 · 들여쓰기 · 링크 · 표 · 그림**을 쓸 수 있습니다.

| | |
|---|---|
| **크기** | `12pt` 처럼 **실제 크기**를 고릅니다 |
| **표** | 격자에서 몇 × 몇인지 짚어 넣습니다 |
| **그림** | 파일을 고르면 본문에 바로 박힙니다 (**1MB 까지**) |
| **참조(CC)** | 이 템플릿으로 보내는 모든 메일에 함께 들어갑니다 |
| **첨부파일** | 템플릿에 붙여두면 모든 메일에 함께 갑니다 (**한 개 10MB 까지**) |

- 꾸미기는 전부 **인라인 스타일**(`<span style="font-size:14pt">`)로 저장됩니다.
  메일 클라이언트는 `<style>` 블록을 지우는 경우가 많고, 옛 `<font>` 태그는
  클라이언트마다 크기 해석이 달라 결과가 들쭉날쭉합니다.
- Word/웹에서 **붙여넣으면 서식 쓰레기를 걸러냅니다** (`<style>`, `class`, 주석 등).
- 도구는 전부 커스텀 단추입니다. 브라우저 기본 `<select>` 는 누르는 순간 편집기에서
  포커스가 빠져 **편집이 들쭉날쭉해지는 원인**이라 쓰지 않습니다.
- 편집기는 브라우저 기본 기능(`contenteditable`)만 씁니다. 폐쇄망에서 외부
  라이브러리를 못 받아도 그대로 돌아갑니다.

> ⚠️ 본문에 **박아 넣은 그림**은 Outlook 등 일부 메일 프로그램이 차단해서 안 보일
> 수 있습니다(메일 안에 `data:` 로 들어가기 때문). 꼭 봐야 하는 그림이면 **첨부로도
> 함께** 붙여 두세요.

### 지원자별 맞춤 — 자리표시자

`{{이름}}` 처럼 적으면 지원자마다 값이 채워집니다.

```
제목  [{{부서}}] 서류 전형 결과 안내
본문  안녕하세요 {{이름}}님,
      서류 전형에 합격하셨습니다.
```

- 도구 모음의 **`＋ 자리표시자`** 를 누르면 묶음별 목록이 뜹니다
  (지원자 / 현재·학력 / 연구·경력 / 채용 / 추가한 열). **찾기 칸으로 좁히고
  누르면 커서 자리에 들어갑니다.** 제목 칸에 커서를 두고 고르면 제목에 들어갑니다.
- 쓸 수 있는 값은 **표의 열 이름 그대로**입니다 — `{{한글_이름}}` `{{박사_학교}}`
  `{{연구분야_키워드}}` 처럼. 추가한 열도 그대로 씁니다.
- **DB 열이 아닌데 쓸 수 있는 것은 넷뿐입니다.** 여기서 만들어 채웁니다.

  | 자리표시자 | 무엇으로 채워지나 |
  |---|---|
  | `{{이름}}` | `한글_이름`, 비어 있으면 `영문_이름` — **`이름` 이라는 열은 없습니다** |
  | `{{부서}}` | 채용 현황에서 배정한 부서 |
  | `{{과제}}` | 채용 현황에서 배정한 과제 |
  | `{{최종상태}}` | 단계 상태에서 계산 (예: `기술 면접 합격`) |

  같은 설명이 편집 화면과 `＋ 자리표시자` 목록에도 붙어 있습니다.
- 값은 **표에 보이는 것과 같은 값**입니다(명칭 사전을 거친 대표명). 화면에서 본 것과
  메일에 나가는 것이 달라지면 안 되기 때문입니다.
- 모르는 자리표시자를 쓰면 편집 화면에 경고가 뜹니다.

### 보내기 전에 한 사람씩 확인합니다

`보내기` 를 누르면 지원자마다 **완성된 제목과 본문**이 표로 나오고, 아래에 **꾸민
그대로의 본문 미리보기**(표·그림 포함)가 붙습니다. 참조와 첨부도 위에 표시됩니다.
보낼 수 없는 사람은 빨간 줄로 이유가 적히고 **체크 자체가 안 됩니다.**

| 못 보내는 이유 | 왜 |
|---|---|
| 이메일 주소가 없습니다 | 보낼 곳이 없음 |
| 값이 빈 자리표시자: 부서 | `안녕하세요 님` 처럼 나가는 사고를 막습니다 |
| 이 템플릿을 이미 받았습니다 | 템플릿별로 **한 번만** |
| 탈락 메일을 이미 받은 지원자입니다 | 아래 참고 |

### 두 가지 규칙은 서버에서 막습니다

1. **템플릿별로 지원자당 한 번만.** 같은 안내를 두 번 받으면 혼란스럽습니다.
2. **탈락 메일을 보낸 지원자에게는 이후 어떤 메일도 나가지 않습니다.**
   템플릿을 만들 때 `탈락 메일` 로 체크해 두면 됩니다. 떨어뜨려 놓고 면접 안내가
   나가는 사고를 막습니다.

화면에서 감추는 데 그치지 않고 **보내기 직전에 서버가 다시 확인**합니다 (화면을 띄운
뒤에 다른 사람이 먼저 보냈을 수 있으므로).

발송이 **실패한 건은 다시 보낼 수 있습니다.** 성공한 것만 '보냄' 으로 칩니다.
누구에게 언제 무엇을 보냈는지는 `발송 이력` 에 남고, 템플릿을 지워도 기록은 남습니다.

### 서버에 맞춘 발송 구현 — `mail_local.py`

사내 API 요구 형식은 서버마다 다릅니다. **`cvtool/clients/mail_local.py` 를 두면
그 구현이 이깁니다.** 이 파일은 git 이 추적하지 않아서 `git pull` 로 덮어써지지
않고, 이 저장소가 `mail.py` 를 고쳐도 서버 쪽 구현은 그대로 남습니다.

서버에서 한 번만:

```bash
cp cvtool/clients/mail.py cvtool/clients/mail_local.py   # 고친 파일을 옮기고
git checkout -- cvtool/clients/mail.py                   # 원본은 되돌린다
```

구현 모듈이 갖춰야 할 것 (`mail.py` 가 그 본보기입니다):

```python
send(받는사람, 제목, 본문, *, html=False, 참조=None, 첨부=None, dry_run=None)
build_url(base, user_id) / build_payload(...) / missing_settings() / MailError
```

`메일` 화면 위에 **지금 어느 구현으로 보내는지** 표시됩니다.

### 사내 메일 API 설정

`.env` 에 넣습니다. **토큰은 코드에 두지 않습니다.**

```
MAIL_DRY_RUN=1          # 기본값. 실제로 보내지 않고 기록만 남깁니다
MAIL_API_URL=https://.../send
MAIL_API_TOKEN=...
MAIL_API_SYSTEM_ID=...
MAIL_API_USER_ID=...
MAIL_SENDER=recruit@회사.com   # 선택
```

> ⚠️ **`MAIL_DRY_RUN` 은 기본이 켜짐(1)입니다.** 설정을 다 맞추고 시험 발송으로
> 확인한 뒤에 `0` 으로 바꾸세요. 연습 모드 기록도 '보냄' 으로 치기 때문에, 진짜로
> 보낼 대상은 연습에서 빼두는 게 좋습니다.

### 진짜로 나가는지 확인하는 법

`MAIL_DRY_RUN=0` 으로 바꾸면 발송 버튼이 **실제로 사내 API 를 호출**합니다. 다만
메일이 정말 도착하는지는 **본문 필드 이름과 인증 방식이 명세와 맞아야** 알 수
있습니다. 그래서 확인 수단을 두 개 뒀습니다.

| | |
|---|---|
| **시험 발송** | 발송 화면에서 내 주소를 넣고 한 통 보내봅니다. **지원자에게 가지 않고 발송 기록도 남지 않습니다** — 몇 번이든 해도 됩니다. API 응답(HTTP 상태 + 본문)을 그대로 보여줍니다 |
| **보낼 요청 내용 보기** | 실제로 보낼 **URL·헤더·JSON 본문**을 그대로 펼쳐 봅니다 (토큰은 가림). 명세와 한 줄씩 맞춰 보세요 |

발송 이력의 `메모` 칸에는 **API 응답이 그대로** 남습니다. HTTP 200 이어도 본문에
실패가 적혀 오는 API 가 있어서, `HTTP 200 {"resultCode":"SUCCESS"}` 처럼 눈으로
확인할 수 있게 해뒀습니다.

**권하는 순서**

1. `MAIL_DRY_RUN=1` 인 채로 `보낼 요청 내용 보기` → 명세와 대조
2. `MAIL_DRY_RUN=0` 으로 바꾸고 재시작 → **시험 발송으로 내 주소에 한 통**
3. 메일함에 도착하면 → 지원자 한 명에게만 먼저 보내고 이력의 `메모` 확인
4. 그다음 여러 명

호출 방식은 사내 API 요구사항을 그대로 지켰습니다 (`cvtool/clients/mail.py`).

- JSON 을 **문자열로 직렬화해 본문에 그대로** 담아 POST
- `userId` 는 **URL 문자열에 직접** 붙임 (`?userId=...`) — `params=` 로 넘기면
  API 가 못 읽는다고 해서. 표준 라이브러리 `urllib` 을 써서 URL 을 넘긴 그대로 보냅니다
- 파라미터 이름 대소문자 유지 (`userId`)
- 참조는 `cc`, 첨부는 `attachments: [{fileName, content(base64)}]`, 꾸민 본문은
  `contentType: HTML`

> ⚠️ **본문 JSON 의 필드 이름과 인증 헤더는 추측값입니다.** 사내 명세를 받으면
> `build_payload()` 함수 하나만 고치면 됩니다 — 나머지 코드는 이 모양을 모릅니다.

## 첨부파일 · CV 없이 등록

**첨부파일** — 지원자마다 자기소개서·포트폴리오 등을 여러 개 붙일 수 있습니다.
CV 원본과 별개이며, 파일명은 지원자_ID 기반으로 저장돼 파일명에 개인정보가
남지 않습니다. 지원자를 삭제하면 함께 지워집니다.

**CV 없이 지원자 추가** — 다른 지원서로 지원한 경우를 위해 `CV 없이 지원자 추가`
버튼이 있습니다. 빈 레코드가 만들어지고 `검토_필요=Y`로 표시되며, 상세 화면에서
직접 채워 넣습니다. 나중에 CV를 첨부해도 됩니다.

## 사용자 · 권한

역할이 셋입니다. 계정은 웹의 `계정` 화면에서 관리합니다.

| 역할 | 볼 수 있는 것 | 할 수 있는 것 | 계정 추가 |
|---|---|---|---|
| **관리자** | 전부 | 전부 + 표 열 구성 + 표 항목 추가 + 메일 | 전원 |
| **채용담당자** | 전부 | 지원자 등록·수정·삭제, 명칭 관리, 부서·과제, 메일 템플릿·발송 | **현업만** |
| **현업** | **자기 과제 지원자만** (과제 매칭 제외) | 채용 상태·비고 | 없음 |

**과제는 부서에 속합니다.** `부서·과제` 화면에서 부서를 만들고 그 아래 과제를
추가합니다. 과제에 초대암호를 걸 수 있고, 현업 계정은 과제에 배정됩니다.

### 최초 관리자

계정이 하나도 없으면 첫 실행 때 `CVTOOL_ADMIN_PASSWORD`(없으면 기존
`CVTOOL_WEB_PASSWORD`) 값으로 `admin` 계정을 만듭니다. 콘솔에 안내가 뜹니다.

로그인 세션은 DB에 저장되므로 **서버를 재시작해도 로그아웃되지 않습니다.**

### 현업이 보는 화면

현업은 **`채용 현황` 탭 하나만** 보입니다. 지원자 목록·변경 이력·메일·업로드·명칭
관리·**과제 매칭**은 메뉴에 아예 안 나오고, **주소를 직접 쳐도 403** 입니다.
로그인하면 곧바로 채용 현황으로 갑니다.

채용 현황 표에는 **배정된 과제의 지원자만** 나옵니다. 그 줄의 `상세` 는 열리지만,
**다른 과제 지원자는 주소를 알아도 못 엽니다** — 상세 화면도, CV 원본도,
첨부파일도 서버에서 막습니다. 자기 과제 지원자를 열어도 **과제 매칭 결과는
안 보입니다** — 거기엔 회사 연구 과제 전체가 들어 있기 때문입니다.

> 화면에서 감추는 것만으로는 부족합니다. 라우트마다 다시 확인합니다.

**새 화면을 만들 때 빠뜨리지 않게** — `tests/test_route_permissions.py` 가
`app.py` 의 모든 주소를 훑어서, 현업에게 열려 있는지 닫혀 있는지 표에 적혀
있는지 확인합니다. 새 주소를 만들고 표에 안 적으면 테스트가 깨집니다. 닫아
둔 주소는 현업 계정으로 **실제로 요청해서 403 이 오는지**까지 봅니다.
(과제 매칭 탭이 현업에게 보이던 일이 있어서 넣은 장치입니다.)

## 여러 사람이 동시에 쓸 때

| 상황 | 어떻게 되나 |
|---|---|
| **서로 다른 칸**을 동시에 수정 | 둘 다 저장됨. 충돌 없음 |
| **같은 칸**을 동시에 수정 | 나중 사람에게 *"다른 사람이 방금 이 값을 A→B로 바꿨습니다"* 알림. **조용히 덮어쓰지 않음** (표에서 고칠 때도 동일) |
| 동시에 저장 | sqlite WAL 모드라 읽기가 막히지 않고, 쓰기는 잠깐 대기 |

행 전체가 아니라 **바꾼 칸만** 저장하기 때문에, 실사용에서는 구글 시트와 체감이
거의 같습니다. 커서가 실시간으로 보이는 수준은 아닙니다.

## 모든 표에서 되는 것

지원자 목록 · 채용 현황 · 명칭 관리 · 계정 · 변경 이력 — **표가 있는 화면은 전부**
같은 도구를 씁니다. 표 위에 줄이 하나 붙습니다.

### 열 제목을 누르면 메뉴가 열립니다

엑셀 필터 단추와 같은 방식입니다. 무엇을 할지 고릅니다.

| 메뉴 | 하는 일 |
|---|---|
| ▲ 오름차순 / ▼ 내림차순 | 그 열로 정렬 (숫자 열은 숫자로, 빈칸은 항상 아래) |
| 정렬 해제 | 원래 순서로 되돌림 |
| **값으로 추리기** | 그 열에 실제로 있는 값 목록 + 건수. 체크한 값만 남깁니다 |
| 이 열 조건 해제 | 이 열에 건 조건만 품 |
| 이 열만 복사 | 머리글 + 그 열 값만 복사 |

- 값이 많으면 메뉴 안의 `값 찾기` 로 좁힙니다. `전체` 로 한 번에 켜고 끕니다.
- **여러 열에 동시에 걸 수 있고**, 걸린 열은 제목이 파랗게 표시됩니다.
- 걸러진 줄의 체크박스는 자동으로 풀립니다 (안 보이는 줄이 딸려 지워지지 않게).

### 복사와 내려받기

| | |
|---|---|
| **범위 복사** | 칸을 **끌어서** 사각형으로 고르고 **Ctrl+C**. 엑셀에 그대로 붙습니다 |
| **엑셀** | `엑셀 내려받기` 버튼 — 지금 화면에 보이는 표 그대로 `.xlsx` |
| **전체 찾기** | `표에서 찾기` 칸 — 모든 열을 한 번에 훑습니다 |

- **머리글은 항상 함께 복사됩니다.** 없으면 엑셀에 붙였을 때 무슨 열인지 알 수
  없어서 옵션 없이 늘 넣습니다.
- 추리고 정렬한 상태 그대로 복사됩니다. 보이는 게 곧 복사되는 것입니다.
- 체크박스 칸과 `상세` 링크 칸은 복사·엑셀에서 빠집니다.
- 사내망은 https 가 아니라 브라우저 클립보드 API 를 못 쓰는 경우가 있어서,
  **브라우저가 직접 처리하는 Ctrl+C** 로 복사되게 해뒀습니다.

### 저장하지 않고 나가면 물어봅니다

명칭 관리·채용 현황처럼 **맨 위 저장 버튼으로 한 번에 저장**하는 화면에서, 고친 칸이
남아 있는 채로 다른 탭을 누르거나 창을 닫으려 하면 확인창이 뜹니다. 저장 버튼을
눌렀을 때는 뜨지 않습니다.

## 표에서 바로 고치기

상세 화면에 들어가지 않고 **표의 칸을 눌러 그 자리에서** 고칩니다.

- 칸을 누르면 입력칸(또는 드롭다운)으로 바뀝니다. **Enter** 저장, **Esc** 취소,
  다른 곳을 눌러도 저장됩니다.
- 저장되면 칸이 잠깐 초록색이 되고, **페이지를 새로 그리지 않습니다** — 넓은 표에서
  스크롤 위치와 검색 조건이 그대로 남습니다.
- 지원자 목록(`/`)과 채용 현황(`/recruit`) 양쪽에서 됩니다.
- 상세 화면과 **완전히 같은 검사·같은 이력·같은 동시편집 처리**를 탑니다. 규칙이
  화면마다 갈라지지 않습니다.
- 고칠 수 없는 칸:
  - `원본_파일명`·`추출_일시` 같은 자동 항목
  - `1저자_해외논문_최우수` 같은 **계산 결과 열** (논문 목록에서 세는 값)
  - **소속·학교·전공** — 명칭 사전이 관리합니다. 표에 보이는 값은 사전을 거친
    *대표명*이라, 그걸 그대로 저장하면 CV 원문 표기가 사라지고 나중에 사전을
    고쳐도 되돌릴 수 없습니다. 지원자 **상세 화면에서 사전에 있는 이름 중
    골라** 넣습니다. 표기 자체가 잘못됐으면 `명칭 관리`에서 고치세요 —
    그러면 이미 등록된 모든 지원자 표에 바로 반영됩니다.
- **현업 계정은 고칠 수 없습니다.** 화면에서 감추는 데 그치지 않고 서버에서
  거부합니다.

서버는 화면과 별개로 다시 검사합니다. 화면에서 감추는 것만으로 끝내지 않습니다.

## 입력 형식 강제

잘못된 값이 표에 들어가면 정렬·필터가 망가지므로 **형식에 맞지 않으면 저장을
거부**합니다. 조용히 고쳐 넣지 않습니다. 표에서 고칠 때도 같은 검사를 거치며,
거부되면 원래 값으로 되돌아가고 이유가 뜹니다.

| 항목 | 입력 방식 |
|---|---|
| `현재_신분` `박사_학위상태` `검토_필요` | **드롭다운만** |
| `박사_시작` 등 연월 | `YYYYMM` 6자리 (`2025.02` → `202502` 로 정규화) |
| `생년월일` | `YYYYMMDD` 8자리. 일자가 없으면 거부 |
| `이메일` | `@` 없으면 거부. 여러 개면 ` \| ` 로 통일 |
| `전공` | 꼬리표 제거 후 저장 |

## 지원자 관리

웹 첫 화면(`/`)이 지원자 표입니다. **업로드는 상단 `CV 업로드` 탭 한 곳**에만
있습니다. 업로드 처리 현황과 `CV 없이 지원자 추가` 도 그 탭에 있고, 분석이 도는
중이면 지원자 표 위에 알림이 뜹니다.

| 하고 싶은 것 | 위치 |
|---|---|
| 지원자 목록 보기 | `/` — 표로 전체 표시 |
| **검색** | 상단 검색창 — 이름·소속·학교·이메일·파일명·ID |
| **검토 필요만 보기** | 검색창 옆 체크박스 |
| **상세 보기** | 각 행의 `상세` 링크 — 전체 항목 + 관리 정보 |
| **한 명 삭제** | 상세 화면의 `삭제` 버튼 |
| **여러 명 삭제** | 목록에서 체크 후 `선택 삭제` |
| **만료분 일괄 삭제** | 만료 건이 있으면 상단에 경고와 버튼이 뜸 |
| **원본 다운로드** | 상세 화면 — 실제 이력서 파일 |
| **다시 분석** | 상세 화면 — 보관된 원본에서 재추출 |
| 엑셀 받기 | `엑셀(.xlsx) 다운로드` (전체) · 표 위 `엑셀 내려받기` (지금 보이는 것만) |
| 엑셀에 붙여넣기 | 칸을 끌어서 고르고 Ctrl+C (머리글도 함께 복사됩니다) |

삭제는 **되돌릴 수 없고** 확인창이 뜹니다. 목록에는 `보관만료` 열이 함께 나옵니다.

`업로드 처리 현황`은 메모리에만 있는 진행 표시입니다. `현황 지우기`는 그 목록만
비우며 **지원자 데이터는 지우지 않습니다.**

### 지우면 서버에서도 지워집니다

지원자를 지우면 **그 지원자 이름으로 저장된 파일이 전부** 사라집니다.

- CV 원본 (`CV-XXXX.pdf`)
- 첨부파일 (`CV-XXXX-att1.docx` …)
- **DB 와 연결이 끊긴 파일까지** — 재분석 중 오류 등으로 남은 파일이 서버에
  그대로 있으면 개인정보가 계속 보관되는 셈이라, 마지막에 지원자_ID 로 시작하는
  파일을 통째로 쓸어냅니다. 파일명이 전부 지원자_ID 기반이라 다른 사람 것은
  건드리지 않습니다.
- 사용자 정의 열 값, 채용 현황 줄도 함께 지워집니다.

변경 이력은 남습니다 — 누가 언제 지웠는지는 기록이어야 하기 때문입니다.

### 데이터가 저장되는 위치

전부 `~/.cvtool/` 아래입니다 (`CVTOOL_DATA_DIR` 로 변경 가능).

| 무엇 | 어디 | 남는가 |
|---|---|---|
| **CV 원본 파일** | `~/.cvtool/files/CV-XXXXXXXX.pdf` | ⭕ 보관 기간까지 |
| **추출 결과**(이름·연락처·이메일) | `~/.cvtool/candidates.db` | ⭕ 보관 기간까지 |
| CV 원문 텍스트 | `candidates.db` 의 `원문_텍스트` 열 | 기본 ❌ / `CVTOOL_STORE_CV_TEXT=1` 이면 ⭕ |
| 학회·저널 목록 | `~/.cvtool/venues.db` | ⭕ |
| 업로드 처리 현황 | 메모리만 | ❌ 재시작하면 사라짐 |

**원본 파일명은 지원자_ID 로 바뀝니다** (`이력서_홍길동.pdf` → `CV-8A1F7854.pdf`).
파일명 자체가 개인정보가 되는 것을 막기 위해서입니다. 다운로드할 때는 원래
파일명으로 되돌려 내려받습니다.

**삭제하면 원본도 함께 지워집니다.** 단건 삭제·일괄 삭제·보관기간 만료 삭제 모두
DB 행과 원본 파일을 같이 지웁니다. 둘이 어긋나면 개인정보가 남기 때문입니다.
DB 에 행이 없는 원본(추출 실패·크래시)은 다음 기동 때 자동으로 삭제됩니다.

**파일 권한:** 디렉터리는 `0700`, DB·원본 파일은 `0600` 으로 잠급니다. 개인정보가
든 파일을 서버의 다른 계정이 읽으면 웹 로그인을 걸어둔 의미가 없기 때문입니다.
기동 시 권한을 다시 조이고, 열려 있으면 경고를 출력합니다.

> 삭제는 `unlink` 이며 디스크 안전 삭제(shred)가 아닙니다. 디스크를 폐기하거나
> 반출할 때는 별도 조치가 필요합니다.

### 원본 열람과 재분석

상세 화면에서 **원본 다운로드**로 실제 이력서를 열어볼 수 있습니다. 추출 결과가
미심쩍을 때 원문과 대조하거나 면접관에게 보여줄 때 씁니다.

**다시 분석**은 보관된 원본에서 텍스트를 새로 뽑아 재추출합니다. 그래서 PDF 파서나
프롬프트를 개선하면 **재업로드 없이 반영**됩니다. 결과는 같은 지원자_ID 에
덮어쓰므로 행이 늘어나지 않습니다.

## 명칭 관리 — 소속 · 학회·저널 · 전공

같은 대상을 다르게 적은 표기에 **표에 보일 이름**을 정합니다. 세 종류가 같은
화면·같은 방식입니다.

```
CV 에 적힌 표기            표에 보일 이름
포항공과대학교(POSTECH)  →  POSTECH
POSTECH                →  POSTECH
(주)가나다소프트          →  가나다소프트
Proc. of ICML 2023      →  ICML      (연도·'Proc. of' 는 저절로 떨어짐)
```

**`소속` 은 학교와 회사를 함께 담습니다.** 지원자의 현재 소속은 학교일 수도 회사일
수도 있어서 사전을 둘로 나누면 같은 곳이 양쪽에 생깁니다. `현재_소속`,
`박사_학교`, `석사_학교`, `학사_학교` 가 모두 이 사전을 씁니다.
(예전 `학교` 탭이 이것으로 바뀌었습니다. **분류해 둔 내용은 그대로 옮겨지고**,
`?kind=학교` 로 저장해 둔 링크도 계속 열립니다.)

1. CV에서 발견된 표기는 **자동으로 등록**됩니다 (학회·저널은 `미분류`로).
2. `명칭 관리` 화면에서 `표에 보일 이름` 을 정합니다. 같은 대상이면 **같은 이름을
   적으면** 되고, 지원자 표에는 그 이름으로 함께 나옵니다.
3. 학회·저널은 등급(최우수/우수/일반/제외)과 국내·해외도 지정합니다.

### CV 에 적힌 표기마다 한 줄

여러 표기를 한 줄로 합치고 대표명만 남기면, 잘못 묶인 걸 나중에 알아채도 **무엇이
잘못 들어갔는지 볼 수도, 떼어낼 수도 없습니다.** 그래서 표기마다 줄이 있습니다.

| 열 | 뜻 |
|---|---|
| **CV 에 적힌 표기** | 발견한 그대로. **바뀌지 않습니다** |
| **발견** | 그 표기가 CV 에서 나온 횟수 |
| **표에 보일 이름** | 지원자 표·엑셀에 나갈 이름. **여기만 고칩니다** |
| **같은 이름으로 묶인 표기** | 지금 이 이름을 함께 쓰는 다른 표기들 |

- 같은 곳이면 **같은 이름을 적으면 됩니다.** 지원자 표에는 그 이름으로 함께 나옵니다.
- **잘못 묶였으면 그 줄의 이름만 다시 고치면 됩니다.** 떼어내기가 한 칸입니다.
- 처음 보는 표기는 묶기 키(소문자·괄호·연도를 뺀 형태)가 같은 줄이 있으면 그 이름을
  물려받습니다. `Proc. of ICML 2023` 이 새로 들어와도 `ICML` 로 보이는 이유입니다.
  물려받은 게 틀렸으면 그 줄만 고치면 됩니다.
- **정렬은 표에 보일 이름 오름차순**이 기본입니다. 사전이니까요.
- 오타로 들어온 표기는 `지움` 으로 뺄 수 있습니다 (다시 CV 에 나오면 새로 등록됩니다).

### 등급은 표기가 아니라 이름에 붙습니다

`ICML` 은 어떻게 적혀 있든 최우수입니다. 그래서 등급·국내해외·학회/저널·IF 는
**표에 보일 이름**에 붙고, 같은 이름을 쓰는 표기들은 저절로 같은 분류를 씁니다.
한 줄에서 등급을 바꾸면 같은 이름의 다른 줄도 함께 바뀝니다.

### 학회와 저널은 한 사전, 구분은 열 하나

같은 곳을 어떤 CV 는 학회로, 어떤 CV 는 저널로 적습니다. 예전에는 그때마다 사전이
둘로 갈라져 **같은 이름이 양쪽에 하나씩** 생겼습니다. 지금은 `학회·저널` 한 탭이고,
학회인지 저널인지는 **`학회/저널` 열**에서 고릅니다.

- 예전 DB 는 열 때 자동으로 옮겨집니다. 별칭으로 숨어 있던 표기까지 **각자 줄로
  되살아나고**, 분류해 둔 등급·국내해외·IF 는 이름에 붙어 그대로 유지됩니다.
- **저널은 Impact Factor 를 적을 수 있습니다.** 옆의 `IF 찾기` 를 누르면
  구글에서 `<이름> impact factor` 를 미리 검색해 둔 창이 새 탭으로 열립니다.

**괄호 표기는 저절로 묶입니다** — `포항공과대학교(POSTECH)` 와 `포항공과대학교`,
`(주)가나다소프트` 와 `가나다소프트` 는 같은 항목입니다. `포항공대` 처럼 아예 다른
표기는 자동으로 합치면 위험해서 담당자가 이름을 맞춰 줍니다.

### 화면 쓰는 법

| 하고 싶은 것 | 방법 |
|---|---|
| 이름·유형·등급·IF 고치기 | 표에서 여러 줄을 고치고 **맨 위 `고친 내용 저장` 한 번** |
| 여러 표기를 같은 이름으로 | 각 줄의 `표에 보일 이름` 에 **같은 이름을 적습니다** |
| 잘못 묶인 것 떼어내기 | 그 줄의 `표에 보일 이름` 만 다시 고칩니다 |
| 많을 때 찾기 | 표 위 `표에서 찾기`, 또는 열 제목 메뉴의 값 목록 |
| IF 확인 | `찾기` — 검색어가 채워진 구글 창이 새 탭으로 열립니다 |

- 고친 칸은 **노랗게** 표시되고, 저장하면 **무엇이 어떻게 바뀌었는지**
  (`포항공과대학교(POSTECH) → POSTECH`) 화면 위에 뜹니다. 안 바뀐 줄은 이력에
  남지 않습니다.
- 이름·유형·등급·IF 변경은 모두 **변경 이력**(`명칭` 탭)에 남습니다.

### 워크샵·세션은 본 학회와 따로 잡힙니다

세션·워크샵 이름이 붙으면 **본 학회와 다른 항목**으로 등록됩니다.

| CV 표기 | 묶이는 곳 |
|---|---|
| `ICML` / `ICML 2023` / `Proc. of ICML 2023` | ICML |
| `ICML (Oral)` — 괄호는 떨어짐 | ICML |
| `ICML Workshop on Federated Learning` | **따로** |
| `NeurIPS Datasets and Benchmarks Track` | **따로** |

일부러 이렇게 뒀습니다. 워크샵 논문을 본 학회와 같은 등급으로 세면 `최우수` 개수가
부풀기 때문입니다. 워크샵은 `일반` 이나 `제외` 로 따로 매기면 됩니다.

**같이 세고 싶다면** 워크샵 줄의 `표에 보일 이름` 을 본 학회와 똑같이 적으면
됩니다. 등급은 이름에 붙으므로 저절로 따라갑니다.

주의 — 워크샵 이름이 조금씩 다르면(`ICML 2023 Workshop on ...` / `ICML 2024
Workshop on ...`) 서로 다른 줄이 됩니다. 연도는 떨어지지만 뒤에 붙는 주제명이
다르기 때문입니다. 이런 것들은 한 번씩 이름을 맞춰주셔야 합니다.

### 고치면 기존 표에 바로 반영됩니다

**원문 표기는 절대 바꾸지 않습니다.** 지원자 레코드에는 CV에 적힌 그대로 두고,
화면·엑셀에 **보여줄 때마다** 사전을 다시 읽습니다.

그래서 관리화면에서 이름이나 등급을 고치면 **이미 등록된 지원자 표가 즉시
바뀝니다.** 재분석할 필요가 없습니다. (예전에는 추출 시점에 값을 굳혀 저장해서
나중에 분류를 바꿔도 반영되지 않았습니다.)

### 등급별 1저자 해외논문 수

등급마다 `표에 개수 열로 낼 등급` 체크박스가 있습니다. 기본은 **최우수·우수**만
켜져 있고, 켜면 `1저자_해외논문_최우수` 같은 열이 표와 엑셀에 생깁니다.
`제외` 는 기본으로 꺼져 있습니다.

## 중복 지원자 검토

업로드할 때 기존 지원자와 대조합니다.

| 수준 | 판정 근거 |
|---|---|
| **중복 확실** | 이메일 일치 / 전화번호 일치 / 이름+생년월일 일치 |
| **중복 의심** | **CV 내용이 많이 겹침** / 이름+박사 학교 일치 / 이름 일치 |

**지원서를 조금 고쳐서 다시 낸 경우**가 `중복 의심`에 걸립니다. CV 원문을 통째로
비교하지 않고 **지문(fingerprint)** 만 저장해 겹치는 정도를 잽니다 — 원문을
복원할 수 없어 개인정보를 덜 남깁니다.

결과는 업로드 처리 현황에 `중복의심`으로 뜨고, `검토_사유`에 어느 지원자와
왜 겹치는지 남습니다. **자동으로 막거나 합치지는 않습니다** — 동명이인일 수 있어
사람이 판단해야 합니다.

## 문제가 생기면

### 추출이 실패할 때

**LLM 응답 원본을 그대로 보여주는 진단 스크립트**를 쓰세요. 아무것도 자르지 않습니다.

```bash
python3 tools/diagnose_llm.py tests/sample_cv.txt
```

`finish_reason`, `reasoning_content` 유무, `content` 원본을 전부 출력하고
guided_json / response_format / 스키마 없음 세 방식을 비교합니다.

| 증상 | 원인 |
|---|---|
| 로그인 화면에서 `CVTOOL_WEB_PASSWORD 가 비어 있습니다` | `.env` 를 못 읽었거나 그 안에 값이 없습니다. **서버 콘솔 첫 줄**에 어느 `.env` 를 읽었는지 찍히니 그걸 확인하세요. `.env.example` 을 고친 건 아닌지도 확인하세요 |
| `출력이 토큰 한도에 걸려 잘렸습니다` | `CVTOOL_LLM_MAX_TOKENS` 를 늘리세요 |
| `JSON 파싱 실패` / `구조화 출력 실패` | 모델 응답을 `tools/check_json.py` 에 넣어보세요. 파서가 어디서 막히는지 단계별로 보여줍니다 |
| 처리 현황에 `텍스트를 추출하지 못했습니다` | 스캔 PDF입니다. OCR이 필요합니다 |
| `ImportError: pypdf` | PDF 라이브러리 미설치 |

### 여러 장으로 실제 품질을 재보세요

한 장이 잘 나왔다고 "웬만한 CV 에 대응된다"고 볼 수 없습니다. 폴더에 CV 를 모아두고
돌리면 어떤 항목이 자주 비는지, 어떤 파일이 실패하는지 한눈에 나옵니다.

```bash
python3 tools/batch_check.py ~/cv_samples
```

결과를 DB 에 저장하지 않는 순수 점검용입니다. 형식(PDF/docx)·길이·언어가 다른
CV 를 섞어서 넣으세요. **`자주 비는 항목`이 곧 다음에 손볼 곳**입니다.

### 추출 품질이 나쁠 때 — 어느 단계가 문제인지 먼저 보세요

추측하지 말고 단계별 출력을 확인하세요. 아무것도 자르지 않고 전 과정을 찍습니다.

```bash
python3 tools/trace_extract.py 이력서.pdf --save trace.txt
python3 tools/trace_extract.py 이력서.pdf --no-two-stage   # 1단계 끄고 비교
```

| 단계 | 여기가 이상하면 |
|---|---|
| `[0] 추출 텍스트` | 파서 문제. 프롬프트를 고쳐도 안 좋아집니다 |
| `[1] 읽기 단계` | 모델이 CV 를 이해 못 함. **여기가 틀리면 뒤는 전부 틀립니다** |
| `[2] 섹션별 JSON` | 이해는 했는데 항목에 잘못 넣음 → 프롬프트 문제 |
| `[3] 정규화 후` | 형식 보정이 값을 망가뜨림 |

`[요약]` 의 빈 항목 목록과 검토 사유를 보면 무엇이 안 뽑혔는지 바로 보입니다.

### 입력 텍스트 자체를 의심할 때

**입력 텍스트가 깨져 있으면 프롬프트를 아무리 손봐도 좋아지지 않습니다.**
PDF를 텍스트로 바꾼 결과를 직접 눈으로 보세요.

```bash
python3 -c "
from cvtool.ingestion.parsers import extract_text
print(extract_text('문제의이력서.pdf')[:3000])
"
```

사람이 읽어서 말이 안 되면 원인은 여기입니다. 2단 편집·표가 많은 학술 CV에서
흔합니다. PDF는 `pypdf`의 **layout 모드**로 원본 배치를 살려 뽑고, 실패하면
기본 모드로 물러납니다(pypdf 4.0+ 필요).

그래도 깨지면 스캔 PDF이거나 레이아웃이 특수한 경우입니다. `/opt/data-gov`의
이미지/OCR 파서를 참고해야 합니다.

| 확인할 것 | 뜻 |
|---|---|
| 텍스트가 뒤죽박죽 | PDF 추출 문제 — 위 참고 |
| `검토_사유`에 `잘랐습니다` | CV가 길어 뒤쪽(보통 논문 목록)이 누락됨. `CVTOOL_MAX_INPUT_CHARS` 를 늘리세요 |
| 논문이 통째로 비어 있음 | 저자 순서를 못 읽은 경우. 지원자 이름을 프롬프트에 넣어 대조하지만, 굵기 표시는 텍스트에서 사라집니다 |
| `현재_신분=불명` | 모델이 판단을 못 한 것. 찍는 것보다 낫습니다 |

### 알려진 주의점

- **이름 추정은 신뢰하지 마세요.** 로마자에서 한글 복원은 원리적으로 불가능합니다
  (`Minjun Kim` → 김민준? 김민중?). 추정한 경우 `이름_추정여부`에 표시되고
  `검토_필요=Y`가 됩니다. **면접 안내 전에 반드시 원문과 대조하세요.**
- 성별·나이·사진·가족사항은 일부러 넣지 않았습니다. 채용절차법상 직무와 무관한
  개인정보 수집이 제한됩니다. 필요하면 인사/법무 확인 후 추가하세요.

  검색·필터, 단건/일괄 삭제, 상세 화면, 2줄 결과, xlsx 다운로드,
  부서·과제명 수정(중복 거부), 표 항목 추가(형식 검사·엑셀 반영·열 구성 노출),
  표에서 바로 고치기(형식 거부·동시편집 충돌·권한 거부·명칭 사전 자동 등록),
  명칭 일괄 저장·원래 표기 보존·'학교'→'소속' 마이그레이션, CV 업로드 탭
- ✅ **실제 브라우저(Chromium)로 확인** — 열 제목 메뉴(정렬·값 추리기·열 복사),
  범위 드래그 복사, 엑셀 내려받기, 부서 선택 시 과제 목록 갱신,
  채용 현황·명칭 관리 일괄 저장, 저장 안 하고 이동할 때 경고, 표기별 한 줄과
  잘못 묶인 것 떼어내기, 기본 열 이름·순서·숨김 변경이 표와 엑셀에 반영,
  인라인 편집, 메일 편집기(글꼴 20종·pt 단위 크기·색·표 격자·그림·자리표시자,
  인라인 스타일로 저장)·참조·첨부·지원자별 미리보기·발송 규칙(1회 제한, 탈락 후
  차단), 현업 계정으로 접근 범위 확인(탭 노출·403·다른 과제 지원자 차단).
  모든 화면에서 JS 오류 0건
- ❌ **실제 LLM 으로 과제 매칭 품질은 미검증** — 이 환경에 vLLM 이 없습니다.
  프롬프트·후보 좁히기·지어낸 과제 걸러내기는 테스트로 고정했지만, 점수와 사유가
  쓸 만한지는 서버에서 CV 몇 장으로 확인이 필요합니다
- ✅ **실제 HTTP 발송 경로 검증** — 가짜 메일 API 서버를 띄워 확인했습니다.
  `MAIL_DRY_RUN=0` 이면 `POST /api/send?userId=...` 로 실제 요청이 나가고,
  `Authorization: Bearer`, JSON 문자열 본문, 참조, base64 첨부까지 그대로 전달됩니다.
  `MAIL_DRY_RUN=1` 이면 서버가 살아 있어도 한 건도 나가지 않습니다
- ❌ **사내 메일 API 자체는 미검증** — 이 환경에서 닿지 않습니다. **본문 필드 이름과
  인증 헤더는 추측값**이라 명세 확인이 필요합니다 (위 '보낼 요청 내용 보기' 로 대조)
- ❌ **실제 LLM 대상 추출 정확도는 미검증** — 서버에서 확인이 필요합니다
- ❌ **PDF layout 모드는 미검증** — 이 환경에 pypdf 가 없습니다. 실패 시 기본 모드로
  물러나도록 해뒀지만, 실제 CV 로 확인이 필요합니다
